## 5. 재시도·fallback·복구 원리

**Local·OpenRouter·CLI 장애와 대기열 초과는 Plan 호출 대신 오류를 반환합니다.** Opus·Haiku·Fable과 선택된 제공자가 처리하지 못하는 네이티브 요청은 여전히 Plan을 사용할 수 있습니다.

```text
호환 Sonnet 요청
  → HTTP 제공자 최초 시도 + 재시도 3회 = 최대 4회 (CLI 백엔드는 1회)
  → 401·402·403은 재시도 없이 오류 + 제공자 복구 대기; 400·404·405·413·415·422는 재시도 없이 요청 오류(회로 대기 없음)
  → 408·429는 별도 일시 오류·제한 정책을 따름
  → 외부로 보내는 요청에서 `metadata`(계정·세션 식별자)와 이전 응답의 서명된 thinking 블록은 제거, 일반 모드에서는 thinking을 요청하지 않음(외부 응답에 thinking이 오면 오류)
  → Plan 전달은 스트림 요청의 헤더 120초·청크 간 무응답 300초를 넘기면 끊음, 요청 본문 상한은 32MiB
  → 모두 실패하면 선택한 제공자의 오류 반환
  → 이후 30초 동안 들어오는 요청도 복구 대기 오류 반환
  → 30초 후 호환되는 실제 요청 1개로 외부 복구 확인
      ├─ 성공: 외부 모델 사용 재개
      └─ 실패: 오류 반환 및 대기 기간 재시작
```

- CLI 백엔드는 위 CLI 절의 단일 시도·설정된 시간 제한을 사용합니다. HTTP 제공자의 일반 모드 외부 시도는 **무응답 30초**(헤더 대기·청크 간 간격)를 넘기면 실패하고, 응답이 계속 오는 동안은 최대 300초까지 기다립니다. Local 전용·compat 모드는 기존의 고정 총 시간 제한을 유지합니다. Plan 응답 시간이나 CLI 자체 재시도는 여기에 추가될 수 있습니다.
- OpenRouter의 기본 재시도 간격은 1초입니다. Local은 혼잡 응답(429·503·529)이나 시간 초과에 한해 재시도 간격을 1→2→4초 기준으로 늘리고 작은 무작위 지연을 더합니다(1회 대기 상한 기본 10초). 빈 응답은 혼잡으로 단정하지 않으며 기존 검증·우회 정책을 따릅니다.
- `Retry-After`는 정수 초와 HTTP-date를 읽고 최대 10분으로 제한합니다. Local 서버가 내부 대기 상한보다 긴 대기를 요구하면 조기에 재시도하지 않고 현재 시도를 종료하며 해당 대기 시간을 회로 복구 대기에도 반영합니다. Local은 Plan 우회 없이 오류를 반환합니다.
- **재시도 단계 예산(P1)**: 한 요청의 재시도 대기(백오프+인정된 `Retry-After`) 합계가 **기본 60초**를 넘으면 남은 재시도를 중단하고 마지막 상태로 오류를 반환합니다(회로는 평소처럼 열립니다). `ROUTE_RETRY_BUDGET_MS`(0~600000)로 조정하며 `0`이면 해제, 소진 누적은 `/api/metrics`의 `retryBudgetExceeded`로 관측합니다.

일반 Local 요청은 원본 대화로 바로 처리하고, 네이티브 기능 제외 사유가 있어 호환 경로로 변환할 수 있는 경우에만 대화·도구 복사본을 만듭니다. 긴 대화의 불필요한 순회와 메모리 할당을 줄이는 최적화이며, 선택 모델·토큰 예산·Plan 우회 조건은 바꾸지 않습니다. 서버의 빈 응답이나 추론 지연을 해결하는 기능은 아닙니다.

### 공유 Local LLM의 요청량 조절

프록시 하나에서 Local로 보내는 요청을 **동시 2개**, **대기 8개**, **최대 대기 60초**로 제한합니다. 실행 자리는 재시도 중에도 유지해 한꺼번에 요청이 몰리지 않게 하며, 취소하면 대기열에서 즉시 빠집니다. 대기열이 가득 차거나 시간이 초과되면 Plan 우회 없이 `local_busy`와 503을 반환합니다. 이 경우는 Local 추론 실패나 회로 차단 횟수에 더하지 않습니다.

대시보드의 프록시 지표에서 실행·대기·한도 초과 건수를 확인할 수 있습니다. AI 점검은 기존 인증이 필요한 `/api/metrics`의 `localAdmission` 필드(`active`, `queued`, `rejected`, `concurrency`, `queueLimit`, `queueWaitMs`)를 사용합니다. `rejected`는 이번 프록시 실행 이후의 대기 한도 초과 누적 건수입니다.

이는 **해당 프록시가 만드는 부하를 제한**하는 기능입니다. 다른 사용자의 요청이나 서버 전체 GPU 사용률을 측정하지 않습니다. 입력 대화·도구·출력 토큰 예산을 임의로 줄이지 않습니다. 수정된 소스는 프록시를 다시 시작한 뒤 적용됩니다. `ROUTE_LOCAL_QUEUE_WAIT_MS`는 새 실행 전에 지정합니다. 60초는 큐 대기 상한이며 추론·재시도까지 포함한 전체 응답 시간 보장은 아닙니다. 대기 8건이 모두 차면 추가 요청은 오류를 반환합니다.

- **회로 차단은 실패 원인을 구분합니다.** 전송 실패·타임아웃·5xx·408·검증 불가한 2xx는 제공자 장애로 보고 회로를 열며, 401·402·403은 제공자 설정 문제로 기존처럼 쿨다운합니다. 반면 429는 제공자가 알려준 `Retry-After`(최대 10분)을 쿨다운으로 사용하고, **요청 자체가 잘못된 4xx는 회로를 열지 않습니다**. half-open 복구 확인은 동시에 하나만 허용되며, 늦게 도착한 이전 시도의 성공·실패는 새 세대의 회로 상태를 덮어쓰지 않습니다. 쿨다운 기본값 30초는 `ROUTE_COOLDOWN_MS`(0~600000)로 조정할 수 있습니다.
- **저지연 TCP 자세**: 소켓별 Nagle 비활성(`setNoDelay`)과 OS keep-alive(초기 15초)를 적용해 작은 JSON/SSE 프레임의 40ms급 지연과 반쯤 끊긴 연결 감지 지연을 줄이며, 요청 수신 전체에도 기존 턴 상한보다 짧은 상한(`requestTimeout`)을 둡니다. 시작 시 외부·Plan 프로바이더 오리진을 한 번씩 배경 HEAD로 **프리우밍(pre-warm)** 하여 첫 실요청의 DNS/TLS/연결 비용을 제거합니다(인증 없는 루트 경로, 실패 무시, `ROUTE_PREWARM=0`으로 해제). 벤치에는 **p95 드리프트 게이트**(`--drift-json <이전 결과>` + `--drift-max-ratio`, 기본 1.4)가 있어 워크로드 p90이 기준 대비 늘면 실패 처리합니다.
- **선택적 스트리밍(P2)**: 스트리밍 응답은 기본 버퍼링을 유지합니다. `ROUTE_STREAM_PASSTHROUGH=1`(전체) 또는 `=2`(검증 가능한 경로에서만, 강제 JSON 검증 경로는 제외)로 켜며, `0`으로 명시 해제할 수 있습니다.
- **HTTP/2 업스트림(P1-2)**: `ROUTE_UPSTREAM_H2=1`이면 기본 업스트림 클라이언트를 `node:http2` 기반으로 바꿔 오리진별 세션을 재사용합니다(https는 h2, 일반 텍스트는 h2c). 동시 턴이 한 연결로 멀티플렉싱돼 HTTP/1.1 헤드오브라인 차단이 없고, 리다이렉트는 실패로 처리하며, 세션 오류 시 다음 요청이 새로 연결됩니다.
- 클라이언트가 요청 본문을 보내다 멈추면 **유휴 기준 타임아웃(기본 30초, `ROUTE_REQUEST_IDLE_TIMEOUT_MS`)** 후 연결을 끊고 점유한 턴을 반납합니다. 느리지만 계속 보내는 큰 업로드는 끊지 않습니다. 연결이 끊긴 요청은 업스트림 읽기·타이머를 정리하고 재시도하지 않습니다.
- 대기 기간이 지나도 백그라운드 진단 요청은 보내지 않습니다. 다음 호환 요청으로 복구를 확인하는 동안 다른 요청은 오류를 반환합니다.
- Plan 요청까지 실패하면 그 오류를 전달합니다. 다른 API 키·제공자로 연쇄 전환하거나 무한 반복하지 않습니다. CLI 자체의 재시도 표시는 라우터 내부의 재시도 횟수와 다를 수 있습니다.
- 외부 응답은 완결성·실제 응답 모델·도구 JSON 등을 검증한 뒤 전달합니다. 외부 스트리밍 응답도 최대 32MiB까지 버퍼링하므로 첫 표시가 늦어질 수 있습니다. 실패한 부분 텍스트나 도구 호출을 전달한 뒤 중간에 Plan 응답을 이어 붙이지 않습니다.
- `tool_use` 종료에 도구 호출이 없거나 `end_turn`에 도구 호출이 있으면 잘못된 응답으로 처리합니다. `max_tokens` 등 출력이 잘린 경우는 별도 종료 사유를 보존합니다. OpenRouter 사용량은 음수가 아닌 안전한 정수로 검증합니다.
- 요청을 취소하면 재시도와 fallback도 중단합니다. 재시도된 외부 추론은 별도 사용량이 발생할 수 있습니다.
- **Plan으로 보낼 때 도구 호출 id를 계약에 맞춥니다.** 외부 제공자가 만든 `Bash:0#abc` 같은 id는 Anthropic의 `^[a-zA-Z0-9_-]{1,64}$` 규칙을 벗어나 Plan 경로에서 400을 유발할 수 있습니다. 프록시는 Plan 전달 직전에 해당 id만 요청 단위로 재할당하고 `tool_use`↔`tool_result` 쌍을 유지하며, 이미 규칙에 맞는 id는 **바이트 그대로** 둡니다(프롬프트 캐시 보존). 외부 경로는 건드리지 않고, 빈 id는 업스트림 호출 없이 로컬 400으로 거부합니다.
- Plan 전용 모델·토큰 수 계산처럼 외부가 표현할 수 없는 요청은 **처음부터 Plan로 우회**합니다. 라우팅 세션이 실험 beta를 끄므로 CLI는 advisor·inline 도구 요청을 만들지 않습니다. `system` 역할 컨텍스트 메시지(text 블록 포함)와 CLI가 상시 보내는 `interleaved-thinking-2025-05-14`·`effort-2025-11-24`·`context-1m-2025-08-07` beta는 모든 모드에서 허용합니다. 제공자가 붙인 `citations`는 응답에 포함되어 다음 요청 이력으로 다시 전송되므로 입력에서도 허용합니다. 이전 응답의 서명된 thinking 블록은 외부 사본에서만 제거하므로, 한 번 Plan으로 우회한 뒤에도 다음 요청은 다시 외부로 갈 수 있습니다. 이 우회는 외부 장애나 복구 성공으로 세지 않습니다.

프록시 동작은 아래 환경변수로 조정합니다(기본값으로 충분하며, 세션 시작 전에 설정).

| 변수 | 기본값 | 의미 |
| --- | --- | --- |
| `ROUTE_REQUEST_IDLE_TIMEOUT_MS` | `30000` | 요청 본문·헤더의 유휴 타임아웃. `0`이면 끔. 느리지만 계속 오는 업로드는 영향 없음 |
| `ROUTE_LOCAL_QUEUE_WAIT_MS` | `60000` | Local 실행 자리 대기 상한(ms), 0~60000. 만료 시 Plan 우회 없이 오류. 실행 중 추론 시간과는 별개 |
| `ROUTE_RETRY_MAX_WAIT_MS` | `10000` | 프록시 내부 재시도 1회 대기 상한. 긴 `Retry-After`는 클라이언트 응답 헤더로 전달 |
| `ROUTE_HANDOVER_TIMEOUT_MS` | `120000` | 무중단 교체 시 진행 중 턴을 기다리는 상한. 초과하면 종료 대신 서비스 복귀(409) |
| `ROUTE_STREAM_PASSTHROUGH` | (꺼짐) | `1` 전체, `2` 검증 가능한 경로에서만(강제 JSON 검증 경로 제외) 프레임을 즉시 전달. `0` 명시 해제. 기본은 버퍼링 |
| `ROUTE_COOLDOWN_MS` | `30000` | 회로 차단 쿨다운(0~600000). 429의 `Retry-After`가 있으면 그 값이 우선 |
| `ROUTE_RETRY_BUDGET_MS` | `60000` | 요청당 재시도 대기 합계 상한(0~600000). `0`이면 해제, 소진은 `/api/metrics`의 `retryBudgetExceeded`로 관측 |
| `ROUTE_PREWARM` | 켜짐 | `0`이면 시작 시 업스트림 오리진 프리웜(HEAD 1회) 해제 |
| `ROUTE_UPSTREAM_H2` | (꺼짐) | `1`이면 업스트림을 `node:http2` 세션으로(오리진별 멀티플렉싱, https h2 / 일반 텍스트 h2c) |
| `ROUTE_STABILIZE_PROMPT_CACHE` | (꺼짐) | `1`이면 외부 전송 직전 system 끝의 `<total_tokens>…` 푸터를 제거해 prefix 캐시를 보존(opt-in) |

## 5-1. 첫 토큰 지연 줄이기 (선택)

기본 동작은 **응답 전체를 검증한 뒤** 한 번에 보내므로, 스트리밍 응답도 생성이 끝나야 화면에 나타납니다. 제공자 실패 시 Plan으로 전환하지 않고 오류를 반환합니다.

```powershell
.\OpenClaude.ps1 -Stream        # 프레임이 검증되는 즉시 전달 (TTFB 단축)
```

| 모드 | 첫 토큰(TTFB) | 실패 시 동작 |
| --- | --- | --- |
| 기본(버퍼링) | 응답 완료 시점 (측정 782ms / 782ms) | 재시도 후 선택한 제공자의 오류 반환 |
| `-Stream`(옵트인) | 첫 유효 콘텐츠 즉시 (측정 **339ms** / 완료 772ms) | 첫 토큰 전에는 같은 정책, **이미 보낸 뒤면** 스트림을 오류로 종료 |

- 전달은 **첫 유효 콘텐츠가 검증된 뒤** 시작합니다. 빈 응답·thinking 전용·깨진 도구 JSON도 같은 제공자별 실패 정책을 따릅니다.
- 환경 변수로도 켤 수 있습니다: `$env:ROUTE_STREAM_PASSTHROUGH = '1'; OpenClaude.ps1`

## 6. 실제로 사용한 모델 확인하기

대시보드와 설정은 공통 색상·카드·입력 컨트롤을 사용하며 보조 정보의 대비를 높였습니다. 대시보드는 넓은 화면에서 **핵심 지표와 요청 흐름을 나란히** 보여주고, 그 아래에 완료 요청·응답 시간·실패율·출력 속도 추이를 정렬합니다. 실행 상태와 진단, 사용량과 활동 기록은 펼쳐서 볼 수 있으며 자동 갱신 중에도 펼침 상태와 상세 제목의 키보드 포커스를 유지합니다. 좁은 화면에서는 세로로 배치합니다. 기존 갱신 주기와 관측 데이터만 사용하며 추가 추론·폴링을 수행하지 않습니다.

Sonnet 선택과 HUD의 모델·비용 표시는 실제 외부 라우팅이나 청구를 보증하지 않습니다. 라우터는 외부 응답의 모델을 검증한 뒤 CLI에 보여주는 모델 이름을 원래 요청 이름에 맞춥니다. **요청별 라우팅 로그와 제공자 사용 기록을 함께 확인하세요.**

로그 예시:

```json
{"event":"route_selected","provider":"openrouter","reason":"replacement"}
{"event":"route_selected","provider":"plan","reason":"native_feature","detail":"unsupported_beta"}
```

라우터 로그(`route_selected` 등)는 기본적으로 숨겨지며 `-Debug`(또는 `python openrouterAdvisor.py --debug`)를 지정할 때만 터미널 stderr에 표시됩니다. 프록시 시작 오류와 `provider_connection_unavailable`은 `-Debug` 없이도 출력됩니다. 라우팅을 확인하려면 `-Debug`로 실행하세요.

| 로그 항목 | 의미 |
| --- | --- |
| `route_selected` + `openrouter` 또는 `local` + `replacement` | 외부 응답 검증을 통과한 대체 경로 |
| `route_selected` + `plan` + `native_feature` | 기존 기능·이력 등을 보존하기 위한 Plan 경로 |
| `route_selected` + `plan` + `fallback` 또는 `circuit_open` | 이전 버전에서 발생한 장애 우회 기록 |
| `external_attempt_failed` | 외부 시도 실패; 시도 번호·상태·오류 분류 확인 |
| `circuit_open` / `circuit_recovered` | 외부 장애 대기 시작 / 외부 복구 확인 |

라우터 자체 진단 로그는 키·요청 본문을 남기지 않는 고정 메타데이터를 사용합니다. 외부 제공자로 보내는 요청에는 실제 대화·코드·도구 정의와 결과가 포함될 수 있습니다. 이 로깅 정책이 외부 서비스의 보관 정책까지 바꾸는 것은 아닙니다.

`native_feature`의 `detail`은 처음 확인된 제외 사유입니다. `token_count`는 토큰 수 계산, `plan_model`은 Plan 전용 모델, `unsupported_beta`는 미지원 beta 헤더입니다. 나머지 `unsupported_*`는 요청 필드·메시지 형식·thinking/output/tool_choice 설정·콘텐츠·도구 정의 검사의 실패를 구분합니다. 로그는 고정 분류명만 기록하며 헤더 원문·질문·키를 기록하지 않습니다. `unsupported_beta`의 `beta_features`는 날짜 접미사가 있는 기능 식별자를 최대 16개 표시하고, `unsupported_beta_count`는 전체 개수를 표시합니다. 비표준 값과 인증정보 형태의 값은 마스킹합니다.

### 실시간 대시보드

```powershell
.\OpenClaudeDashboard.ps1
```

기본 주소는 **`http://127.0.0.1:8787/`**입니다. 상태 조회 `GET`은 읽기 전용입니다. 설정 화면의 저장·연결 검사·블랙박스 기록처럼 상태를 바꾸는 `POST`에는 로컬 쓰기 토큰이 필요합니다. 토큰은 페이지 HTML에 넣지 않고, 시작할 때 출력되는 `"write_url"`(예: `http://127.0.0.1:8787/#token=…`)로만 전달됩니다. 브라우저는 이 주소로 접속하는 순간 해시에서 토큰을 읽고 주소창에서 지우며, 이후 **그 탭의 `sessionStorage`**에만 보관합니다. 덕분에 탭 안에서 화면을 이동하거나 새로고침해도 쓰기가 유지되고, 탭을 닫으면 토큰도 사라집니다. 같은 PC의 다른 프로세스가 페이지를 `GET`해 토큰을 가져가거나 다른 탭으로 복사할 수는 없습니다. 토큰 없는 주소로 열면 읽기는 되지만 상단에 안내 배너가 뜨고 쓰기는 `token_required`로 거부됩니다. 토큰은 저장소의 `.dashboard.token` 파일(같은 사용자 권한의 파일)에 보관되어 **대시보드를 재시작해도 유지**되며, 이미 열어 둔 탭도 계속 쓸 수 있습니다. 토큰 새로 만들려면 그 파일을 삭제한 뒤 대시보드를 다시 시작하거나 `DASHBOARD_TOKEN` 환경 변수로 직접 지정하세요. **자동 회전은 제공하지 않습니다**(탭의 `sessionStorage`와 같은 사용자 파일 기반 설계 유지, audit C2). 주고받은 핸드오프 nonce는 7일이 지나고 포트가 닫힌 세션의 것이면 attach 후보에서 제외되며(audit C3), 오래 죽은 세션의 인스턴스 디렉터리는 30일 후 자동 정리됩니다(audit D5). 이전 대시보드는 아래 신원 검증을 통과한 경우에만 종료하고 같은 포트를 다시 사용합니다. 다른 프로그램이 그 포트를 쓰고 있으면 임의 포트로 옮기지 않고 오류로 알립니다. 빈 포트로 대체하려면 `python routeDashboard.py --allow-port-fallback`을 사용하세요.

이전 인스턴스 종료는 `.dashboard.pid`에 기록한 **pid와 프로세스 생성시각이 모두 일치할 때만** 수행합니다(`python routeDashboard.py --stop` 포함). Windows에서 pid가 재사용된 경우·자기/상위 프로세스·구버전(신원 없는) 기록은 종료하지 않고 `identity_mismatch`/`own_tree_pid`/`identity_unverifiable` 한 줄로 보고하며, 그 기록은 다음 시작 때 덮어씁니다. 업그레이드 직후 이전 버전 대시보드가 남아 있다면 그 인스턴스를 한 번 직접 종료(`Ctrl+C`)한 뒤 시작하세요. 비Windows에는 생성시각 조회 수단이 없어 이 검증이 불가능하므로, 안전을 위해 종료를 거부합니다.

**갱신 주기**는 상태에 따라 달라집니다: 라우팅이 진행 중이면 2초, 유휴면 10초, 브라우저 탭이 숨겨져 있으면 15초. 화면 상단에는 한 줄 요약(`오늘 43.8M토큰 · $1.42 · 남은 한도 $48.25 · 우선 확인: …`)이 표시됩니다.

대시보드 상단의 요약 지표에서 현재 서비스와 요청·응답 상태를 먼저 확인하고, 바로 아래 그래프에서 최근 60분 외부 모델·Plan 라우팅 비율과 최근 24시간 시간대별 토큰 사용량을 확인할 수 있습니다. 시간대별 상세 수치도 펼쳐 볼 수 있습니다. 그래프는 기존 수집값을 사용하며 모델에 추가 요청을 보내지 않습니다. 좁은 화면에서는 지표가 여러 줄로 배치됩니다.

**인사이트** 카드는 숫자를 나열하는 대신 *무엇이 달라졌고 왜 그런지, 다음에 무엇을 할지*를 우선순위로 제시합니다. 각 항목은 근거 수치(칩)를 함께 보여주며, 해당 배너와 같은 원인이면 배너를 중복 표시하지 않습니다.

서버 쪽 계산은 읽기 전용이며 세션 재시작·설정 저장·제공자 호출을 하지 않습니다. 알림 권한을 허용하지 않아도 배너와 탭 제목은 그대로 동작합니다.

**프로세스 상태 카드**는 실행 중 프록시가 직접 보고한 값을 표시합니다: **RSS·힙 사용량**, **이벤트 루프 지연 p95/max**, 프로세스 PID. 이벤트 루프 지연은 프록시 자체 작업(본문 파싱·헤더/필드 검증·로그·메트릭 기록)이 요청 처리를 막은 시간으로, 업스트림 지연과는 별개입니다. **100ms 이상 지연이 발생하면 시각과 함께 최근 3건을 표시**해 어떤 시점의 작업(스냅샷·GC 등)과 겹쳤는지 추적할 수 있습니다. 이벤트 루프 지연 p95가 **250ms 이상**이면 능동 경고를, RSS가 **1.5GiB 이상**이면 메모리 경고를 표시합니다. 라우트 로그는 줄마다 개별 동기 쓰기 대신 **10ms 비동기 배치·상한 큐**로 묶어 기록하고, 카드에 **로그 쓰기 max·큐·드롭**을 함께 표시합니다. 프로세스 카드에는 **GC 횟수/max와 동기 블로킹 상위 구간(body_parse·diagnostics·metrics_serialize)** 도 함께 표시해 `eventLoopSpikes` 시각과 대조할 수 있습니다. 스냅샷 폴링은 **ETag/304**로 캐시되어 데이터가 바뀌지 않으면 본문 전송과 DOM 재렌더를 생략합니다(`x-dashboard-cache: HIT/MISS`). `/api/metrics`와 같은 세션 토큰이 필요하며, 지표 파일(`.proxy-metrics.json`) 기록은 **비동기**로 수행해 요청 처리 이벤트 루프를 막지 않습니다.

**코드 변경은 자동 반영됩니다.** 대시보드는 `routeDashboard.py`·`routeConfig.py`·`localProcessTree.py`가 바뀌면 스스로 재시작해 새 페이지를 제공하고, 실행 중 프록시가 이전 코드로 시작됐으면(`proxy_hash` 불일치) **진행 중 요청이 없는 시점에 같은 포트·토큰으로 자동 takeover**를 요청합니다. Claude Code 세션을 끊지 않고 새 프록시 코드가 적용되며, 시도·실패는 `.auto-update.log`에 남습니다. 대시보드가 실행 중이 아니거나 takeover가 지원되지 않는 모드면 다음 세션 시작 시 반영됩니다.

**여러 세션을 동시에 실행해도 됩니다.** 대시보드는 `.usage-stats/instances/*/handoff.json`을 스캔해 살아 있는 모든 세션을 찾고, 별도 선택이 없으면 가장 요청이 많은 세션을 표시합니다. 표시 중인 세션이 살아 있는 동안 다른 세션을 재시작해도 화면이 초기화되지 않으며, 표시 세션이 사라지면 새 빈 세션이 아니라 남은 세션 중 가장 활발한 세션으로 전환합니다. 세션이 2개 이상이면 헤더의 **세션 선택**으로 바꿀 수 있고, 선택은 `.dashboard.session`에 저장되어 대시보드가 자동 재시작해도 유지됩니다. 재시작된 프록시 자체의 시계열은 새 프록시 기준으로 다시 시작됩니다.

**레이아웃은 내용과 별개로 고정됩니다.** 폭 1400px 이상에서 상단 **한눈에 보기**·**요청 흐름** 카드는 560px로 고정되고, 긴 모델명·상태는 한 줄 말줄임, 지표 값은 말줄임, 인사이트 본문은 3줄 클램프로 처리됩니다. 토큰 수나 문장이 바뀌어도 아래 차트·진단 카드가 위아래로 밀리지 않습니다(좁은 화면은 가독성을 위해 자동 높이).

**지금 필요한 것**은 조치할 경고가 있을 때 지표보다 먼저 표시됩니다. 경고를 **확인·1시간 미루기·해결·다시 열기**로 관리하고, 상태는 `.dashboard-attention.json`에 저장됩니다. 확인·미룸·해결 이력은 **사용량과 활동 기록**에서 볼 수 있습니다. 세션별 **재시도 상태**(속도 제한/재시도 횟수/Retry-After)도 표시되어 외부 서비스 제한과 로컬 부하를 구분할 수 있습니다.

진단 API의 `metrics.externalTimeouts`는 외부 시도 제한 종류와 헤더·본문 진행 단계를 집계합니다. `routingTimingMs`의 `externalHeaders`, `externalFirstBody`, `externalTimeout`은 최근 최대 512개 시도의 시간 분포입니다. 본문 진행 중 timeout은 느린 클라이언트의 영향도 포함할 수 있으며 모델 서버의 원인으로 단정할 수 없습니다. `latencyMs.chunkCadenceMs`는 스트리밍 응답의 **업스트림 청크 간격(캐던스) 분포**로, 프레임 생성 리듬이 느려지는지 한눈에 확인할 수 있습니다. 새 지표는 프록시 재시작 후 수집됩니다.

`externalTimeouts.localAttempts`는 종료된 Local 시도(사용자 취소 포함)를 입력 요청 크기(64KiB 이하, 256KiB 이하, 초과)와 시도 시작 시 이 프록시의 Local 슬롯 점유 수(1개, 2개 이상)로 나눠 timeout 건수와 함께 집계합니다. 재시도도 별도 시도이며, 슬롯 점유에는 재시도 대기도 포함됩니다. 서버 전체 부하나 토큰 수를 의미하지 않습니다.

**세션별 모니터링 표**에서 동시에 실행 중인 세션을 비교할 수 있습니다. 세션별 요청 수·요청/분, 외부/Plan 경로, 실패/취소, 진행·실행·대기, 외부 p95, 출력 토큰/초, 입력/출력 토큰, RSS·이벤트 루프 p95, 마지막 활동을 표시합니다. 진행·대기 요청이 있거나 이벤트 루프 p95가 250ms 이상이면 그 세션에 **부하** 표시가 붙고, **표시** 버튼으로 상세 카드의 기준 세션을 바꿀 수 있습니다.

**한눈에 보기**는 상태 LED·현재 라우팅·모델, 최근 60분 외부/Plan 비율 막대, 요청·실패율·관측 속도·외부 p95 타일, 표시 세션의 프로젝트·브랜치·포트와 활성 세션 수, 오늘 토큰·비용·잔액을 한 카드에 보여줍니다. 세션별 모니터링에는 **프로젝트명·브랜치·cwd**가 표시되며, 새 세션은 실행기가 정확한 cwd/저장소/브랜치를 기록하고 컨텍스트가 없는 기존 세션은 Claude 트랜스크립트에서 매칭한 값임을 **추정**으로 표시합니다. 두 세션의 작업이 다르면 이 열에서 바로 구분할 수 있습니다.

**최근 요청 추이**는 프록시에서 완료 시각 기준으로 집계한 최근 최대 60분의 요청 수·평균 응답 시간·실패율·관측 출력 속도를 곡선으로 표시합니다. 빈 구간은 연결하지 않으며, 분별 상세 수치를 펼쳐 볼 수 있습니다. 추이 기록은 메모리에만 보관하므로 새 프록시를 시작한 뒤부터 쌓이고 재시작 시 초기화됩니다. 실패율은 성공·실패를 분모로 하며 취소는 제외합니다. 응답 시간에는 취소를 포함합니다.

**요청 흐름**은 Claude Code, Claude-Cheat 프록시, 모델 서비스의 관계를 SVG 경로와 처리 바로 표시합니다. 진행 요청은 숫자와 상태로 표시하고, 새 요청이나 관측된 외부 응답은 짧은 움직임으로 표시합니다. Local의 실행 슬롯에는 재시도 대기도 포함됩니다.

입력·출력 입자는 완료된 외부 성공 응답에서 보고한 토큰의 갱신 간 증가분을 나타냅니다. 방향별 최대 24개이며 실시간 토큰 생성이나 개별 요청의 정확한 시간 순서는 아닙니다. 한 갱신 구간의 입력 또는 출력이 10,000토큰 이상이면 처리 바가 잠시 따뜻한 색으로 강조됩니다. 이는 실제 온도나 서버 과열을 뜻하지 않습니다.

첫 조회는 비교 기준을 만드는 **첫 관측**입니다. 이후 완료 응답이 없으면 **새 응답 없음**, 사용량을 보고하지 않으면 **미보고**로 표시합니다. Plan·실패·취소 응답의 토큰은 추정하지 않으며, 비교할 수 없는 제공자는 부분 관측으로 표시합니다. 흐름을 보기 위해 별도 추론 요청이나 폴링을 추가하지 않습니다.

움직임은 기본적으로 켜져 있으며 **움직임 끄기**로 현재 페이지에서 멈출 수 있습니다. 숨긴 탭이나 화면 밖에서는 입자를 표시하지 않고, 수치는 움직임 설정과 관계없이 표시합니다. 사용량 화면의 조회 시각은 대시보드가 응답을 읽은 시각입니다.

관측 토큰의 숫자와 보고 건수는 함께 표시하며, 아래 막대의 최대 기준은 10,000토큰입니다. 입력에는 별도 캐시 토큰을 합산하지 않습니다. 공유 서버 전체의 GPU 부하나 순수 모델 생성 속도는 이 화면에서 알 수 없습니다.

화면 오른쪽 상단의 상태 표시에는 마지막 라우팅 상태와 현재 주의 상황이 색과 글자로 표시됩니다. Plan은 빨강, 외부 모델은 초록, 주의 상태는 갈색 계열이며 유휴·미확인은 별도로 표시합니다.

성능 카드는 기존 프록시 집계를 사용하며 별도 추론 요청을 보내지 않습니다. 출력 토큰/초는 제공자가 사용량을 보고한 성공 응답의 출력 토큰 합계를 전체 요청 시간 합계로 나눈 관측치입니다. 대기·네트워크·재시도를 포함하며 같은 제공자의 여러 모델이 섞일 수 있습니다. 완전히 검증된 스트리밍의 보고 사용량도 포함하고, Plan·취소·실패·사용량 미보고 응답은 제외합니다. GPU 이용률과 순수 모델 생성 속도는 제공하지 않습니다. 새 토큰 계측은 프록시를 새 코드로 다시 시작한 이후의 요청부터 쌓이며 과거 누락분은 복구하지 않습니다.

**모든 연결점을 같은 기준으로 봅니다.** Local LLM·OpenRouter·CLI는 모두 세션 기록의 토큰과 경로 로그의 결정·시도 실패를 같은 방식으로 집계합니다. CLI 표시 중에도 사용량 카드를 숨기지 않으며, CLI가 토큰을 보고하지 않은 경우에는 0으로 추정하지 않고 "미보고"와 출처를 함께 표시합니다. 연결점별 표는 최근 60분 라우팅 로그를 실행기 세션(인스턴스)별로 분리해 보여 주며, 경로 로그를 회전해도 `--- proxy start … continued=1 … ---` 표식으로 같은 세션임을 유지합니다. 실패율은 프록시의 `failed`에서 취소(`aborted`)를 뺀 완료 응답 기준으로 계산합니다.

**화면 문구도 데이터와 같은 기준을 씁니다.** 네 화면(대시보드·설정·사용량·블랙박스)의 구조·문구·엔드포인트 목록은 실제 API 응답과 대조해 점검했습니다([메뉴 감사](docs/DASHBOARD-MENU-AUDIT.ko.md)). 기록이 없는 구간은 `0건`이 아니라 **최근 60분 이벤트 없음**으로 표시하고, 헤더·범례·지표 이름은 제공자와 무관하게 "외부 모델"로 통일했습니다. 도움말의 HTTP API 목록은 UI가 실제로 호출하는 13개 주요 엔드포인트를 담습니다. 설정 화면은 저장 429(`rate_limited`)와 CLI 백엔드 응답 코드(`backend_version_unverified` 등)를 한국어로 안내하고, 실행할 수 없는 Grok 선택지는 "(미검증 · 실행 불가)"로 표시합니다. 블랙박스 상태 줄은 기록 시작 시각과 (있을 때) 폐기된 기록 수를 함께 보여 줍니다.

**모니터링 자체도 감시합니다.** 서버 스냅샷이 30초 이상 갱신되지 않거나 갱신에 실패하면 경고 배너와 상태 카드에 `snapshot_stale`/`snapshot_refresh_failed`로 표시하고 `/api/status` 종료 코드를 3으로 올립니다. 가격 조회 실패는 1분 뒤 재시도하며(성공 단가는 1시간 캐시), 계정 한도 캐시는 API 키별로 분리합니다. 임의의 리다이렉트는 따라가지 않아 제공자 키가 다른 출처로 전달되지 않고, Local 모델 목록 URL은 추론 URL과 같은 출처일 때만 키를 받습니다. 라우팅 이벤트가 상한(2,000건)에 닿으면 "이벤트 창"에 일부만 집계됐다고 표시합니다.

**턴은 정확히 한 번만 셉니다.** Claude Code는 같은 응답을 스트리밍 중 여러 번 기록하고 `/resume`·포크는 히스토리를 복사하므로, 파일별 합산은 같은 턴을 여러 번 셉니다(이 PC의 7일 창에서 assistant 행의 42%가 중복). 대시보드는 `message.id`+`requestId`(없으면 `msg:`/`uuid:` 폴백)로 턴을 식별하고, 중복 행은 턴 수를 늘리지 않으며 더 커진 토큰 차액만 반영합니다. 따라서 이전 버전보다 턴 수가 낮게 보이는 것이 정상입니다.

**비용에는 상태가 붙습니다.** OpenRouter 문맥에서 단가를 조회하면 **추정(estimated)**, Plan 경유분은 구독 포함 **included(귀속용 $0)**, Local 또는 단가를 확인하지 못한 외부 토큰은 **unknown(비용 null)** 으로 표시합니다. 현재 추정은 조회한 한 모델의 단가를 집계된 외부 토큰에 적용하므로, 보관 기간에 여러 모델·서비스의 기록이 섞이면 모델별 실제 청구를 재현하지 못합니다. 누적 토큰·비용은 **보관 폴더에 남은 세션 파일 전체**를 합산하므로(파일 수정시각 기준 7일) 오래된 턴이 최근 수정된 파일에 들어 있으면 포함될 수 있고, **오늘** 값만 각 행의 시각으로 거릅니다. 캐시 생성 토큰은 5분·1시간 TTL을 분리해 1시간 단가가 있으면 그 값으로, 없으면 표준 단가로 계산합니다. 실제 청구는 제공자 기록을 기준으로 확인하세요.

**최근 요청의 모델**은 경로 로그가 있을 때 프록시가 응답을 전달하기 직전에 남긴 값입니다. CLI에 표시되는 모델 이름은 요청 별칭(`claude-sonnet-5-5` 등)일 수 있습니다. 현재 프록시에 로드된 기본 모델과 최근 요청의 처리 모델은 [모델 확인 기준](#현재-모델-확인과-중복-선택의-범위)에 따라 구분합니다.

집계 캐시(`.usage-cache.json`)는 턴 소유권 원장을 포함해 실사용 7일 창에서 약 **0.5MB**입니다(합성 2,000파일·10만 턴 기준 5.4MB, 상한 20만 클레임에서 오래된 파일 단위로 축출). 캐시 버전이 바뀌면 한 번 전체 재스캔합니다.

키·프롬프트·요청 본문은 표시하지 않고, 경로 로그와 대화 원문을 수정하지 않습니다. 설정 저장은 실행기 폴더의 `openclaude.config.yaml`과 백업에 반영하며, 실행 중에는 PID 기록·집계 캐시 같은 운영 파일도 관리합니다. 대시보드는 CLI 세션과 별개 프로세스이므로 함께 띄워 두면 됩니다.

### 설정 편집과 연결 테스트

설정 화면의 **설정 변경 이력**에서 대시보드로 저장한 모델·서비스 선택 등의 변경을 조회하고 복원할 수 있습니다. 인증정보, 서버 주소, 실행 경로와 보안 설정은 이력에 저장하거나 복원하지 않습니다. 조회 후 설정 파일이 변경되면 복원이 거절되므로 이력을 다시 조회하세요. 서비스 초기화는 해당 서비스의 이력도 삭제합니다. 파일을 직접 편집한 변경은 이력에 기록되지 않습니다.

설정은 대시보드와 **분리된 페이지**(`http://127.0.0.1:8787/settings`)에서 관리합니다. 상단 내비게이션의 **설정**으로 이동하세요. 두 페이지는 같은 서버·같은 쓰기 토큰을 사용하며, 토큰은 `write_url`의 `#token=…` 조각으로만 전달됩니다.

| 항목 | 동작 |
| --- | --- |
| 저장 | 지정된 키만 수정하고 다른 주석·섹션·줄바꿈(CRLF)·BOM은 그대로 유지합니다. 이전 파일은 **바이트 그대로** `openclaude.config.yaml.bak`에 남깁니다. 해당 서비스 섹션이 아직 없고 예전 `.env`에 값이 있으면, 섹션을 새로 만들 때 그 값을 함께 옮겨 자격증명이 가려지지 않게 합니다. 동시 저장은 파일 잠금으로 직렬화되며, 같은 파일을 읽을 수 없으면(인코딩·문법 오류) 덮어쓰지 않고 오류와 줄 번호만 알려 줍니다 |
| 비밀값 | 브라우저로 다시 전송하지 않습니다(`sk-or-…cd0`처럼 마스킹). 입력을 비우면 저장된 값을 유지하고, 새 값을 넣을 때만 교체합니다 |
| 서버 주소 | Messages·HTTP 예외·모델 목록 주소도 키처럼 일부만 보입니다(`http://12•••••.1:11434/v1/messages`: 호스트는 앞뒤 2자만, `user:pass@`·쿼리는 가림, 표준 경로가 아닌 사용자 지정 path는 `/•••`). 원문은 브라우저로 전송하지 않고, 비우면 유지합니다 |
| 지우기 | 선택 항목(HTTP 예외·모델 목록 주소)은 **지우기** 버튼으로 삭제합니다(`POST /api/config`의 `clear` 목록). 필수 항목과 키는 지울 수 없습니다 |
| 검증 | 모델 ID 형식, 키 형식, Local URL 규칙(루프백·HTTPS·동일 출처)을 저장 전에 확인하며 실패하면 파일을 건드리지 않습니다 |
| 보호 | 설정 조회(`GET /api/config`)와 저장(POST) 모두 `write_url`로 받은 쓰기 토큰이 필요하고, POST는 동일 출처일 때만 허용합니다(다른 사이트에서 호출 불가). 토큰은 페이지 HTML에 없으며 같은 PC의 다른 프로세스가 `GET /`로 얻을 수 없습니다 |
| 연결 테스트 | **모델 확인**은 모델 목록만 조회하고, **추론 테스트**는 OpenRouter 16토큰·Local 512토큰 한도로 1회 호출합니다(과금 또는 서버 자원 사용 가능). Local은 선택 모델 ID·정확한 `OK` 답변·정상 종료까지 확인합니다. 저장하지 않은 폼 값으로 검사할 때 반영되는 것은 **모델 ID·타임아웃**뿐이며, 서버 주소·API 키·CLI 실행 파일은 항상 저장된 값만 사용합니다(작성 중인 주소로 저장된 키가 나가는 것을 막기 위함). 동시에 한 검사만 실행되고, 초과 요청은 `test_busy`로 거부됩니다 |
| 모델 선택 | **목록** 버튼으로 제공자 모델을 검색해 고릅니다. 제공자와 CLI 종류에 따라 조회 가능 항목이 다르며, 목록에 없으면 모델 ID를 직접 입력할 수 있습니다. `GET /api/models`는 세션 토큰이 필요합니다 |
| 적용 시점 | 저장한 설정은 **새 세션부터** 적용됩니다. 실행 중인 세션은 재시작하세요 |
| 오류 안내 | 저장 요청이 429로 제한되면 `rate_limited`, CLI 백엔드가 거부하면 `backend_version_unverified` 같은 알려진 코드를 한국어 문구로 표시합니다. 실행할 수 없는 Grok 선택지는 "(미검증 · 실행 불가)"로 표시합니다 |

### 원본 Sonnet과 블랙박스

설정의 기본 실행 서비스에서 **원본 Claude Sonnet**을 고르거나 `OpenClaude.ps1 -Provider Sonnet`을 실행하면 Claude Code에 `--model sonnet`을 전달해 프록시 없이 시작합니다. 기존 실행 중 세션은 변경하지 않습니다. 프록시 주소·외부 인증·모델 별칭 등과 충돌하는 사용자 환경이나 설정이 발견되면 값을 출력하거나 변경하지 않고 안내 후 중단합니다. 관리형 정책이나 응답 모델은 별도로 확인하지 못하므로 실행 요청만으로 실제 first-party 모델 사용을 보장하지 않습니다.

원본 Sonnet에서는 지원되는 Claude Code 버전일 때 기본적으로 Opus Advisor를 요청합니다. 사용자가 직접 지정한 Advisor나 비활성 설정은 우선하며, 계정·모델·조직 정책에 따라 실행이 거부되거나 실제 Advisor가 사용되지 않을 수 있습니다. Advisor는 전체 대화와 도구 결과를 검토하며 추가 사용량이 발생합니다. 직접 실행은 프록시를 통하지 않아 Advisor 호출·토큰의 대시보드 실측은 제공되지 않습니다. Local·OpenRouter·CLI의 외부 모델 요청에서 Advisor만 별도로 실행하는 기능은 아직 없습니다. [Advisor 지원 조건](https://code.claude.com/docs/en/advisor)

### 사용량 통계

상단 **사용량** 메뉴에서 새로 수집한 요청의 일·주·월 추이와 제공자·요청 모델·실제 보고 모델·실행기별 집계를 확인합니다. 주는 월요일에 시작하며 표시 시각은 이 컴퓨터의 시간대를 사용합니다. 각 실행기는 독립 ID와 기록을 사용하고, 이전 단일 세션 자료와 신규 원장은 중복 합산하지 않습니다. 기존 세션과 직접 실행한 Sonnet은 새 원장에 관측되지 않으며, CLI가 실제 모델이나 토큰을 보고하지 않은 경우는 미보고로 남습니다.

기록은 `.usage-stats/`의 로컬 SQLite와 실행기별 이벤트 파일에 저장되며 프롬프트와 도구 내용은 포함하지 않습니다. 13개월은 조회 범위이며 자동 삭제 정책이 아닙니다. 사용량은 청구액이나 GPU 부하가 아니라 보고된 요청·토큰과 지연의 관측치입니다. 기록 실패·강제 종료나 비동기 종료 시 마지막 이벤트가 유실될 수 있어 누락 경고와 수집 시작 시점을 확인하세요.

사용량 화면은 보이는 동안 30초마다 기존 캐시를 조회하고, 숨겨진 탭에서는 자동 조회를 멈춥니다. 일시적인 조회 실패 시 같은 기간의 마지막 성공 결과를 유지하고 시각과 실패 상태를 표시합니다. 실행기 상태의 요청·실패 수는 선택한 일·주·월이 아닌 해당 실행기 시작 이후의 누적값입니다. 실행 중인 세션의 확인 파일이나 수집할 이벤트 파일이 없는 과거 폴더는 각 검사의 32개 처리 한도를 차지하지 않습니다. 디렉터리 항목이 4,096개를 넘으면 탐색을 제한하고 부분 수집 경고를 표시하며, 한도 밖 항목은 자동으로 발견되지 않을 수 있습니다.

상단 **블랙박스** 메뉴에서 기록을 시작하고 문제가 발생하면 **문제 시점 표시**를 누릅니다. 기본 진단은 경로·오류 분류·시간·집계 등 제한된 정보만 저장합니다. **상세 기록**을 명시적으로 선택한 뒤 새 세션을 시작하면 해당 세션의 이력에서 연결 이후 추가된 대화·도구 입출력을 문제 표시 시 수집합니다. 기존 세션 이어가기, 사용자 `--settings`, 관리 정책의 훅 차단 등에서는 연결되지 않을 수 있으며 화면에서 연결 상태를 확인해야 합니다. 상태 줄에는 기록 시작 시각과 (있을 때) 폐기된 기록 수가 함께 표시됩니다. 원본 Sonnet은 프록시를 거치지 않으므로 프록시 수치는 해당 원본 세션의 실측이라고 볼 수 없습니다.

기록은 프로젝트의 `.blackbox/recording.json`에 최대 2 MiB·256개 이벤트로 보관되며 오래된 기록은 제거됩니다. 상세 기록은 민감정보를 포함할 수 있고 패턴 마스킹으로 모든 비밀을 제거한다고 보장할 수 없습니다. Windows에서 해당 폴더의 접근 권한은 상위 폴더 ACL에 의존하므로 공유 환경에서는 저장 위치 권한을 직접 확인하세요. 상세 입력은 완결된 최근 레코드만 최대 64 KiB로 제한하며, 오래되거나 지나치게 큰 내용은 생략될 수 있습니다. 저장된 파일은 Git에서 제외됩니다.

설정 화면에서 OpenRouter 또는 Local LLM을 선택하면 **인증 정보 삭제**와 **서비스 설정 초기화**를 사용할 수 있습니다. 인증 삭제는 해당 서비스의 API 키만, 초기화는 키·모델·주소 등 해당 서비스의 관리 설정을 지웁니다. 저장 파일, 기존 `.bak`, 해당 서비스의 구형 `.env`에 있는 관리 항목을 정리하며 다른 서비스의 설정과 기본 서비스 선택은 유지합니다. 초기화한 서비스가 기본값이면 다음 실행 전에 다시 설정하거나 다른 서비스를 선택하세요.

삭제 확인 후 되돌릴 수 없습니다. 여러 파일을 정리하는 중 실패하면 일부 파일에 값이 남을 수 있으므로 화면의 오류를 확인하고 다시 시도하세요. 실행 중인 세션은 이미 읽은 값을 계속 사용할 수 있어 종료 후 다시 시작해야 합니다. 환경변수, 다른 위치에 복사한 파일이나 백업, 관리 항목 외 임의의 주석, 제공자 서버에 발급된 키는 삭제하거나 폐기하지 않습니다. 키를 더 이상 사용하지 않으려면 제공자에서도 폐기하세요.

### 현재 모델 확인과 중복 선택의 범위

모델 정보는 다음 네 가지를 구분해서 확인합니다.

| 정보 | 확인 방법과 의미 |
| --- | --- |
| 설정된 모델 | 서비스 설정의 모델 ID입니다. 저장한 변경은 다음 세션에 적용됩니다 |
| 프록시에 로드된 모델 | `/api/diagnostics`의 `session.loaded_model`입니다. 인증된 프록시가 시작 시 읽은 기본 모델이며, 다음 실행용 설정과 다를 수 있습니다 |
| 연결 검사 모델 | 세션 시작 전 최소 추론에서 응답 모델 ID가 지정값과 일치하는지 검증합니다. 일반 모드는 실패해도 경고 후 세션을 시작할 수 있습니다 |
| 최근 요청의 모델 | 프록시가 응답을 검증한 뒤 남긴 라우팅 기록입니다. 대시보드의 실제 사용 모델은 이 기록을 기준으로 합니다 |

실행 중인 Claude Code의 `/model` 선택값을 대시보드가 실시간으로 읽지는 않습니다. 세션이 없거나 아직 요청을 보내지 않았다면 설정값·과거 기록만으로 현재 모델에 연결됐다고 판단하면 안 됩니다. **모델 확인**은 목록 조회이고 **추론 테스트**와는 다릅니다.

실행기는 기본적으로 OpenRouter 세션에 경로 로그·메트릭 파일 경로를 설정합니다. 활성 세션에서는 이전 세션의 로그·코드 해시를 현재 상태에 사용하지 않고, 인증된 프록시의 최신 메트릭과 현재 세션 로그를 비교합니다. 현재 로드 모델은 `session.loaded_model`, 최신 요청의 소속은 `last_route.current_session`으로 구분하세요. Plan 경로나 세 서비스 중 실제 처리 모델을 알 수 없는 경우에는 최근 처리 모델을 추정하지 않고 `null`로 표시합니다. 구버전 프록시가 모델을 보고하지 않거나 민감값이라 생략된 경우에도 로드 모델은 `null`입니다.

최근 60분·10분의 경로 비율은 현재 세션의 실제 로그만 집계합니다. 해당 구간 로그가 없는 Local 세션에서는 비율을 0%로 단정하지 않고 기록 없음으로 안내하며, 세션 전체의 누적 요청·외부/Plan 건수는 **프록시 처리량** 카드에서 확인합니다. 누적 카운터를 최근 구간 통계로 바꾸어 표시하지 않습니다.

모델 선택 목록에서는 같은 서비스의 **동일한 모델 ID를 한 번만** 표시합니다. 앞뒤 공백을 제거한 ID가 같으면 첫 항목의 메타데이터를 유지하며, 대소문자나 `:latest` 같은 접미사가 다른 ID는 임의로 합치지 않습니다. 항목 선택은 입력칸만 채우고, 저장 버튼을 눌러야 설정이 바뀝니다. 요청별 기본·대체 제공자 선택과 별칭 충돌 검사도 적용됩니다. 같은 모델 이름을 가진 서로 다른 서버나 여러 세션의 실행 자체를 금지하는 기능은 아닙니다.

### CLI를 모델 백엔드로 사용하기

#### 서비스 전환 전 확인

설정 화면에서 Local LLM 또는 CLI의 설정을 저장하고 기본 실행 서비스로 선택합니다. 저장한 값은 **다음 세션**부터 적용되며, 실행 중인 세션과 진행 중인 요청은 바뀌지 않습니다. 작업과 하위 에이전트가 끝난 뒤 Claude Code를 정상 종료하고 `OpenClaude.ps1`을 다시 실행하세요. 실행 후 대시보드의 현재 세션과 최근 요청 경로를 확인합니다.

Plan은 현재 설정에서 직접 선택하는 독립 서비스가 아니라, 일반 라우팅 모드에서 지원되지 않는 기능이나 외부 요청 실패 시 사용할 수 있는 구독 경로입니다. Local에서 CLI로 자동 전환하거나 세 서비스를 실시간으로 부하 분산하지 않습니다. 응답이 이미 전달된 요청은 중복 실행을 피하기 위해 다른 경로로 재시도하지 않습니다.

설정 저장은 연결 성공을 뜻하지 않습니다. 연결 또는 추론 테스트는 실제 모델 호출로 사용량이 발생할 수 있습니다. CLI에는 별도 로그인과 검증된 버전이 필요하며 Grok 백엔드는 아직 사용할 수 없습니다. 서비스별 기존 설정은 보관되지만 CLI 종류를 직접 바꿀 때에는 모델과 실행 파일의 호환성을 다시 확인하세요.

설정 화면에서 CLI 설정의 종류를 선택하고 저장한 뒤, **기본 실행 서비스**를 CLI로 지정합니다. `.\OpenClaude.ps1`으로 새 세션을 실행하며 일회성 실행은 `.\OpenClaude.ps1 -Provider CLI`입니다. CLI 종류를 바꾼 경우 모델·실행 파일도 다시 확인하세요.

CLI 카드의 **CLI 자동 검색** 버튼은 `GET /api/cli` 감지 결과로 지원 백엔드(Claude Code·Codex·Grok)의 설치 여부·버전·경로를 다시 조회하고, 선택한 종류(없으면 첫 감지 항목)의 실행 파일 경로를 `실행 파일 경로`에 채웁니다. 감지는 지원하는 백엔드 이름과 표준 설치 위치·PATH만 확인하며, 임의의 CLI 명령을 PATH 전체에서 찾아 추가하지는 않습니다. 채운 값은 자동 저장되지 않으므로 **저장**을 눌러야 적용됩니다.

CLI 모델 목록에서 Codex를 선택하면 Codex의 로컬 모델 캐시를 읽어 선택지를 표시합니다. 캐시는 계정별 최신 권한이나 백엔드 실행 성공을 보장하지 않으며, 목록 조회는 추론을 실행하지 않습니다. 캐시가 없거나 읽을 수 없으면 모델 ID를 직접 입력하세요. Claude Code와 Grok은 검증된 목록 조회 방식이 없어 직접 입력해야 합니다. Grok 백엔드는 별도로 아직 실행할 수 없습니다.

CLI 세션의 대시보드는 프록시에서 진행 중인 CLI 요청과 429 응답, 오류 범주, 최근 60분 입·출력 토큰 및 사용량 보고 표본을 표시합니다. CLI 어댑터는 동시 실행 한도 4개를 넘으면 대기열에 넣지 않고 거절합니다. 프록시 진행 요청 수는 실제 CLI 프로세스 수나 서버 GPU 부하가 아닙니다. 토큰 보고율의 분모는 CLI 성공 응답이며 미보고 응답은 0토큰으로 계산하지 않습니다. 프록시가 분류하는 4xx에는 CLI 백엔드의 내부 검증 오류도 포함될 수 있습니다. 세션을 다시 시작해야 새 지표가 수집되며, 이전 프록시의 누락 지표는 미보고로 표시합니다.

**CLI 프로세스 실행 시간**은 프로세스 시작 직전부터 종료 관측까지의 시간입니다. 시작 비용·CLI 내부 준비·통신이 포함되며 순수 모델 추론 시간이 아닙니다. 검증된 성공 응답의 최근 최대 512개만 집계하고 실패·취소·미보고 응답은 제외합니다. CLI가 실제 모델명을 보고하지 않으면 설정 모델명을 실제 값으로 대신 표시하지 않습니다.

격리된 실제 Codex 연동 확인은 `python tests/live_cli_smoke.py --run`으로 명시적으로 실행합니다. 저장된 CLI 설정과 로그인을 사용하여 실제 추론 한 건을 보내므로 사용량이 발생할 수 있습니다. 임시 작업 공간에서 합성 도구 **제안**만 확인하며 실제 도구는 실행하지 않습니다. 이 검사는 프록시·전면 Claude Code·Agent Teams·SSH/MCP 전체 조합 검증을 대신하지 않습니다.

백엔드의 합성 도구 왕복은 `python tests/model_quality_probe.py --provider local --run`으로 별도 확인할 수 있습니다. `local` 대신 `openrouter` 또는 `cli`를 지정하면 해당 저장 설정을 사용합니다. 실제 추론을 최대 두 번 실행해 사용량과 Local 서버 부하가 발생하며, 도구·명령은 실행하지 않습니다. 첫 응답의 Lookup 호출과 인자를 확인한 후 예측할 수 없는 합성 결과를 전달해 다음 답변을 검사합니다. 모델 보고·요청 모델과의 정확한 일치 및 입출력 사용량 보고 여부도 별도로 표시합니다. 이 검사는 프록시와 Claude Code를 통과하지 않고 Plan으로 우회하지 않습니다. 통과해도 실제 코딩 품질, MCP·SSH·Skills·Agent Teams 또는 원본 Sonnet과의 동등성은 확인되지 않습니다. Sonnet은 이 검사에서 지원하지 않습니다.

설정 화면의 **도구 왕복 검사** 버튼도 같은 검사를 수행합니다. 먼저 해당 서비스의 변경 사항을 저장해야 하며, 검사 시작 시 저장된 설정을 사용합니다. 도구 왕복 결과와 보고 모델의 일치·불일치·미확인은 별개로 표시합니다. 결과는 현재 실행 세션의 모델 검사 결과가 아닙니다. 대시보드에서 실행한 최근 검사 결과의 제한된 상태는 프로세스 메모리에만 보관해 읽기 전용 진단에 표시하며, 대시보드를 재시작하면 사라집니다. 한 대시보드 프로세스에서는 동시에 하나의 검사만 실행할 수 있고, 별도 명령행 검사까지 제한하지는 않습니다. 화면을 닫아도 진행 중인 추론이 즉시 취소되지는 않습니다. CLI 호출의 토큰 상한은 백엔드 정책에 따릅니다.

화면과 SSH/MCP·Skills·Plugins·hooks·권한 처리는 원본 Claude Code가 맡습니다. 백엔드 CLI는 대화와 도구 목록을 받아 엄격한 JSON으로 답변 또는 도구 호출을 제안하며, 실제 도구 실행은 전면 Claude Code가 수행합니다. 백엔드에서 자체 도구·프로젝트 규칙을 실행하는 이중 에이전트 동작은 허용하지 않습니다.

Codex 백엔드의 임시 작업 폴더는 읽기 전용으로 격리되지만, 이 설정이 앞단 Claude Code의 프로젝트 접근 권한을 결정하지는 않습니다. 백엔드에는 앞단 도구의 실제 권한 결과를 따르도록 안내합니다. 앞단 도구가 실제로 쓰기를 거부한다면 해당 권한·호스트 설정을 확인해야 하며, 이 안내는 권한 제한을 우회하지 않습니다.

Local LLM과 OpenRouter에도 도구 권한을 실제 호스트 지침과 도구 결과에 따라 판단하라는 안내가 전달됩니다. 사용자가 명시한 읽기 전용 정책이나 실제 도구 거부는 그대로 존중합니다. 원본 Sonnet과 Plan 우회 요청에는 이 안내를 삽입하지 않습니다.

| 항목 | 동작과 제한 |
| --- | --- |
| 지원 판정 | 설치 여부와 백엔드 검증 여부를 구분합니다. 현재 허용 버전은 Claude Code `2.1.312`, Codex `0.165.0`이며 다른 버전은 재검증 전 거부합니다. |
| Grok | 목록과 감지는 제공하지만 현재 설치 버전의 도구 차단이 검증되지 않아 `backend_version_unverified`로 거부합니다. |
| 연결 확인 | 명시적인 연결 테스트와 시작 시 검사에서 고정 `OK` 요청을 실제 백엔드에 보냅니다. 해당 CLI의 별도 로그인이 필요하며 사용량이 발생할 수 있습니다. 감지만으로 연결 성공을 표시하지 않습니다. |
| 실행 격리 | 셸 없이 빈 임시 작업 폴더에서 실행합니다. 백엔드 도구·MCP·hooks 등을 검증된 프로필로 차단하고, 라우터 인증·주소는 전달하지 않습니다. 프롬프트와 응답은 메모리에서 처리합니다. |
| 도구·이력 | 광고된 도구 이름과 인자 JSON 객체 형식, 호출·결과 짝, 선택 제약을 검사합니다. **도구 인자가 광고된 `input_schema`를 만족하는지는 검증하지 않습니다.** 미지원 입력은 Plan으로 보낼 수 있으며, 잘못된 Local 응답은 오류를 반환합니다. |
| 출력 토큰 | 요청의 `max_tokens`는 백엔드 프롬프트에 포함되지만 CLI 생성에 정확한 토큰 상한으로 강제되지 않습니다. 엄격한 요청별 출력 한도가 필요한 경우 CLI 백엔드를 사용하지 마세요. |
| 재시도 | CLI 백엔드는 한 번 호출한 뒤 실패 시 Plan으로 전환합니다. 중복 백엔드 추론을 위한 자동 재시도는 하지 않습니다. 제한 시간은 10~120초(기본 60), 동시 요청은 최대 4개입니다. 취소 시 소유한 자식 프로세스를 정리합니다. |
| 모델·사용량 | 요청한 모델과 실제 보고된 모델을 분리합니다. CLI가 실제 모델·사용량을 보고하지 않으면 미확인으로 남기며 프로토콜 식별자를 실제 모델명으로 표시하지 않습니다. |
| 상태 API | `/api/diagnostics`는 읽기 전용이며 CLI 추론이나 로그인을 시작하지 않습니다. CLI 원문 출력·오류나 인증 정보는 대시보드에 노출하지 않습니다. |

원본 Claude Code 옵션은 PowerShell에서 `-CliArgs`로 전달할 수 있습니다.

```powershell
.\OpenClaude.ps1 -CliArgs @('--resume', 'session id', '--plugin-dir', 'C:\my-plugin')
.\OpenClaude.ps1 -CliArgs @('--help')
```

Python 직접 실행은 `python openrouterAdvisor.py -- --resume "session id"`처럼 `--` 뒤에 인자를 넣습니다. 도움말·버전·관리 명령은 라우팅 및 추론 검사 없이 원본 CLI로 전달합니다. 제한 모드와 충돌하는 옵션은 명확한 오류로 거부합니다. 전면 Claude Code 로그인과 선택한 백엔드 로그인은 별개이며, 이 기능은 모든 모델의 도구 이해 능력이나 Sonnet과 동일한 품질을 보장하지 않습니다.

### 요청 구성 계측 (CLI 후보 측정)

대시보드의 **요청 구성 (CLI 후보)** 카드는 요청을 **모델 계열 × 도구 유무**로 센 것입니다. 텍스트 전용 CLI가 처리할 수 있는 요청(도구·tool_result·이미지 없음)이 실제로 얼마나 되는지 재려는 용도입니다.
- 프록시가 요청마다 **내용 없는** 이벤트 한 줄(`request_shape`: 계열, 도구, 도구 블록, 비텍스트, 스트림 여부)을 경로 로그에 남깁니다. 모델 ID·프롬프트·도구 이름은 기록하지 않습니다.
- OpenRouter 세션에서만 기록됩니다(경로 로그가 있을 때). `/api/status`의 `request_shapes`로도 볼 수 있습니다.
- 참고: Opus·Haiku·Fable 요청은 지금도 항상 Plan으로 가므로, CLI 후보가 되려면 도구 없는 **Sonnet** 요청이어야 합니다. 이 수치가 작으면 CLI 라우팅은 효과가 작습니다.

### 스크립트·에이전트용 상태 API

페이지를 열지 않고도 한 번에 상태를 확인할 수 있습니다.

```powershell
python routeDashboard.py --status           # 한 줄 JSON + 종료 코드
python routeDashboard.py --status --pretty  # 읽기 좋게
python routeDashboard.py --status --usage    # 토큰·비용까지 집계(느림)
python routeDashboard.py --status --offline  # 외부 호출·현재 프록시 확인 생략, 저장된 기록만 조회
```

| 종료 코드 | 의미 |
| --- | --- |
| 0 | 정상 (외부 경로 사용 중이거나 유휴) |
| 2 | 현재 Plan 경로 |
| 3 | 심각 경고 (회로 차단·잔액 부족 등) |
| 4 | 라우팅 기록 없음 (아직 실행기 세션 없음) |

출력에는 `state`, `provider`, `reason`, `detail`, **`model`**, `last_event_age_seconds`, `window_counts`, `plan_reasons`, `failures`, `alerts`, `account`가 포함됩니다. 대시보드를 띄워 둔 경우 `GET /api/status`로 같은 내용을 받습니다. 두 경로 모두 키·프롬프트·요청 본문을 포함하지 않습니다.

실행 중인 프록시는 자체 카운터를 `GET /api/metrics`로 제공합니다(같은 세션 토큰 필요, 127.0.0.1 전용). 요청 수, 외부·Plan 경로 분포, p50/p95 지연, 재시도·스트림·회로 횟수, 송수신 바이트를 담습니다. 대시보드는 인수인계 파일의 토큰으로 이 응답을 확인한 경우에만 **현재 세션**으로 표시하며, 인증된 응답의 카운터를 사용합니다. 토큰·포트·PID는 설정 응답에 포함하지 않습니다.

### 버전 확인과 업데이트 알림

대시보드 상단과 실행기 시작 줄에 지금 실행 중인 빌드가 표시됩니다. 제품 버전은 `VERSION` 파일(예: `1.0.0`)에서, 리비전은 git에서 읽어 **`v1.0.0 (4148f2f)`**처럼 함께 보여 줍니다. 커밋되지 않은 변경이 있으면 `*`가 붙습니다.

일반 `OpenClaude` 실행 시 원격 `origin`의 현재 추적 브랜치를 한 번 확인합니다. 작업 트리가 깨끗하고 활성 세션이 없으며 원격의 정식 `VERSION`이 더 높고 fast-forward가 가능할 때만 업데이트한 뒤 실행기를 다시 시작합니다. 추적되지 않은 파일을 포함해 로컬 변경이 있거나 충돌·진행 중인 Git 작업이 있으면 보존하고 건너뜁니다. 설정된 원격이 `origin`이 아니거나 정식 세 자리 버전을 비교할 수 없는 경우에도 자동 적용하지 않습니다. 네트워크 오류 시 기존 버전으로 실행하며, 적용이 일부만 진행된 경우에는 확인을 위해 실행을 중단합니다.

일반 실행은 대시보드를 백그라운드에서 시작하거나 기존 인스턴스를 재사용하고 모니터링 페이지를 엽니다. 포트의 소유자를 확인할 수 없으면 다른 프로세스를 건드리지 않고 건너뜁니다. `-Help`, `-Version`, `-Setup`, 진단, `-Takeover`, `-Print`는 이 자동 실행 대상이 아닙니다.

업데이트가 중단되어 `.openclaude-update-incomplete` 표시가 남으면 자동 재기동과 일반 실행이 중단됩니다. 저장소 상태와 파일을 확인해 복구한 뒤에만 이 표시 파일을 제거하고 다시 실행하세요.

```powershell
python routeDashboard.py --version           # 요약 + 지금 원격 확인
python routeDashboard.py --version --json    # 전체 JSON(스크립트용)
python routeDashboard.py --version --offline # 네트워크 확인 생략
python openrouterAdvisor.py --version        # 실행기에서 같은 확인
.\OpenClaude.ps1 -Version                    # 위와 동일
```

명시적 `--version` 조회는 `current`, `behind`, `ahead`, `diverged`, `different`, `unknown`, `disabled` 중 확인 결과를 보고합니다. 이 조회 자체는 읽기 전용입니다.

- 대시보드는 원격 버전을 주기적으로 확인하지 않습니다. 배지는 로컬 버전을 표시하며 클릭하면 로컬 정보를 다시 읽습니다.
- `ROUTE_UPDATE_CHECK=0`으로 자동 업데이트를 끌 수 있습니다. 원격·브랜치 선택 환경 변수는 명시적 `--version` 조회에 적용되며, 자동 적용은 현재 `origin` 추적 브랜치에만 허용합니다.
- 릴리스 기준은 `VERSION` 파일입니다. 릴리스할 때 `VERSION`을 올리면 대시보드·실행기·`--version`이 같은 이름을 씁니다.

`.proxy-metrics.json`에 남은 카운터도 볼 수 있지만, 현재 프록시가 확인되지 않으면 **지난 실행 기록**으로 표시하고 현재 세션의 실패·지연 인사이트에 사용하지 않습니다. `proxy_stale`은 마지막 프록시 시작 로그의 코드와 현재 소스가 다른지를 뜻합니다. 이 값만으로 구버전 프록시가 지금 실행 중이라고 판단하지 않습니다.

### AI 디버깅용 상태 점검 API

**`GET http://127.0.0.1:8787/api/diagnostics`**는 AI와 스크립트가 읽을 수 있는 버전 지정 JSON을 반환합니다. 대시보드가 실행 중이어야 합니다. 루프백·Host 검사를 적용하며, 비밀값을 제외한 진단 조회에는 세션 토큰이 필요하지 않습니다.

```powershell
Invoke-RestMethod http://127.0.0.1:8787/api/diagnostics | ConvertTo-Json -Depth 8
# 또는
curl.exe --fail --silent http://127.0.0.1:8787/api/diagnostics
```

이 조회는 설정을 수정하거나 외부 API·추론을 호출하지 않습니다. 현재 프록시가 있으면 인수인계 토큰으로 로컬 `/api/metrics`를 한 번 확인하고, 그 응답과 설정·라우팅 기록·기존 화면 캐시의 상태를 조합합니다. 토큰·키·서버 주소·파일 경로·PID·프롬프트·본문·원문 예외는 반환하지 않습니다. 모델 값에 URL·절대 경로·민감값이 포함되면 모델도 `null`, 상태는 `redacted`로 표시합니다.

| 필드 | AI가 확인할 내용 |
| --- | --- |
| `schema_version` | 현재 `1`; 응답 형식을 식별하는 버전 |
| `status` | `ok`, `degraded`, `error`; 진단 요청 성공 여부와 별개인 구성요소 상태 |
| `checks[]` | `component`, `status`, 기계 판독용 `code`, 권장 조치 코드 `action` |
| `configuration` | 저장된 기본값, 다음 실행 서비스, 설정된 모델, 서비스별 설정 완성 여부 |
| `session` | 인증된 프록시의 존재와 실제 로드된 기본 모델, 대체 제공자, 장애 시 Plan fallback 정책. 네이티브 예외는 별도 |
| `last_route` | 최근 요청의 모델·시각·현재 세션 여부와 확인 가능한 fallback 오류 분류 (`fallback_failure`) |
| `capabilities` | 자동 기능 검사는 하지 않아 도구·이미지·thinking·스트리밍·문맥 한도는 `unknown`. `tool_roundtrip_evidence`는 이 대시보드의 명시적 백엔드 검사 결과만 표시 |
| `metrics` | 현재 프록시의 요청·실패·재시도·회로 개방 누적 수; 과거 파일을 현재 수치로 사용하지 않음 |
| `snapshot` | 화면 캐시의 존재, 마지막 성공 갱신 후 경과 초, 갱신 오류 유무 |
| `next_check` | 별도 인증이 필요한 모델 목록 점검 요청 정보; 자동 실행하지 않음 |

도구 검사 근거는 저장 설정의 값이 검사 당시와 같을 때만 최대 24시간 표시합니다. 값이 바뀌었다 돌아온 경우 다시 일치할 수 있으며, 서버 모델·CLI 실행 파일·인증 상태의 변화까지 확인하지 않습니다. `passed`는 합성 도구 왕복 결과일 뿐 모델 일치(`model_match`) 및 Claude Code·프록시 전체 기능의 보증이 아닙니다. 별도 CLI 검사 결과는 수집하지 않습니다.

AI는 다음 코드로 원인과 조치를 구분할 수 있습니다.

| 코드 | 의미 / 조치 |
| --- | --- |
| `configuration_incomplete` / `routing_configuration_invalid` | 설정이 없거나 잘못됨; 설정 화면 확인 |
| `provider_choice_required` | 기본값 없이 두 서비스가 설정됨; 기본 서비스 저장 |
| `session_not_running` | 현재 프록시가 확인되지 않음; 세션 실행. 대시보드 자체의 장애를 뜻하지 않음 |
| `proxy_model_matches_settings` | 프록시가 보고한 로드 모델과 현재 설정이 같음; 외부 추론 성공 증거는 아님 |
| `model_settings_changed` | 설정 모델과 로드된 모델이 다름; 같은 실행 모드를 유지하며 세션 재시작 |
| `proxy_model_unreported` / `proxy_model_redacted` | 구버전 프록시가 모델을 보고하지 않거나 민감값이라 생략됨; 설정값으로 추정하지 않음 |
| `proxy_provider_mismatch` | 인수인계 기록과 프록시가 보고한 제공자가 다름; 세션 상태 확인 후 같은 모드로 재시작 |
| `upstream_not_checked` | 이 요청에서는 외부 모델 연결을 검사하지 않음; 오류와 구분 |
| `snapshot_building` | 최초 화면 집계가 아직 완료되지 않음; 잠시 후 다시 조회 |
| `snapshot_refresh_failed` / `snapshot_stale` | 화면 갱신 실패 또는 마지막 성공 후 30초 초과; 프록시 상태와 따로 확인 |
| `request_failures_recorded` | 현재 프록시에 실패 요청이 누적됨; 최근 라우팅과 별도 연결 검사 확인 |

진단 JSON 생성에 성공하면 구성요소에 오류가 있어도 **HTTP 200**을 반환하므로 AI는 본문의 `status`와 `checks`를 확인해야 합니다. 잘못된 Host는 403, 진단 처리 자체의 실패는 500과 고정 오류 코드 `diagnostics_failed`를 반환합니다. 구버전 프록시에는 로드 모델이 없을 수 있으며, 이 경우 `session.loaded_model`은 `null`입니다. `session.plan_fallback`은 라우팅 정책으로, 스트리밍 전달이 시작된 뒤에도 fallback을 보장한다는 뜻은 아닙니다.

연결 검사가 필요하면 기존 **`POST /api/test`**에 `{"provider":"local","mode":"metadata"}`를 보내 모델 목록만 조회할 수 있습니다. 이 요청은 런처가 출력한 `write_url`의 쓰기 토큰(`x-dashboard-token`) 인증이 필요합니다. 실제 추론은 별도의 `mode:"inference"` 요청이며 호출 비용이 발생할 수 있습니다. 진단 API의 `ok`와 로컬 프록시 응답만으로 외부 추론까지 성공했다고 판단하지 마세요.

도구 왕복 검사는 같은 인증으로 `{"provider":"local","mode":"tool_roundtrip"}`을 보냅니다. `local`, `openrouter`, `cli`를 지원하며 추가 `values`를 받지 않고 저장 설정만 사용합니다. 응답은 도구 결과·모델 일치·사용량 보고 여부를 포함하는 상태 메타데이터이며 원문 대화나 키를 반환하지 않습니다. 검사 중 중복 요청에는 `probe_busy`를 반환합니다. 실제 호출은 최대 두 번이며 소켓별 제한이 전체 검사 시간 상한을 보장하지는 않습니다.

### 설정·실행기·프록시·대시보드의 연결 기준

- 모델·크레딧 카드의 서비스는 **인증된 현재 세션 → 저장된 기본값 → 최근 라우팅 기록 → 설정된 서비스** 순서로 정합니다. 기본값을 바꿔도 현재 세션의 서비스는 바뀌지 않습니다.
- 최근 요청의 처리 라벨은 실제 라우팅 기록을 따릅니다. 한 세션에서 두 서비스를 함께 쓰는 경우, 기본 서비스와 마지막 요청의 제공자가 달라도 구분합니다.
- Local을 표시할 때는 OpenRouter 크레딧·단가를 조회하지 않고 **적용 대상 아님**으로 안내합니다. 공통 토큰 집계는 **외부·Local·CLI 토큰**으로 표시하며, Local에 OpenRouter 단가를 적용하지 않습니다.
- 서비스·모델·단가 버전이 바뀌면 토큰·비용 화면 캐시를 다시 계산합니다. 최초 페이지 응답은 OpenRouter 조회를 기다리지 않습니다.
- 설정을 저장한 뒤에도 기본값과 현재 세션 표시를 유지합니다. 설정 읽기가 실패하면 이를 빈 설정으로 취급하거나 기본값을 덮어쓰지 않습니다.
- `--offline`은 외부 API와 로컬 프록시 확인을 모두 생략합니다. 따라서 오프라인 응답의 `active_session`은 `null`이며, 라우팅 상태·종료 코드는 저장된 기록을 기준으로 해석해야 합니다.

연결 흐름만 다시 확인하려면 다음 검사를 사용하세요. 임시 설정과 로컬 Node 프록시를 사용하며 실제 Claude CLI·외부 추론 호출은 실행하지 않습니다.

```powershell
python -m unittest discover -s tests -p test_route_dashboard.py -k test_real_proxy
node --test tests/dashboard_dom.test.mjs
```

화면 검사는 Python이 실제 HTML에 넣는 JavaScript를 실행합니다. 소스 문자열 일부만 추출하는 방식으로는 인증 처리나 동적으로 추가된 코드의 누락을 놓칠 수 있기 때문입니다. 이 검사는 브라우저의 시각적 배치나 실제 외부 모델의 응답 품질까지 보증하지는 않습니다.
