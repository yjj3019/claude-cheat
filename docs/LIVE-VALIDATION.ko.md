# 연결·장애 복구 검증 절차

[한국어 안내](../README.md) · [English guide](../README.en.md)

개인 테스트 환경, 계정 사용량·청구 내역, 세션 식별자, 실제 대화·설정 파일·진단 로그는 공개하지 않습니다. 이 문서는 재현 가능한 점검 절차와 합성 입력을 사용한 제한된 검증 결과를 담습니다.

## OpenRouter 호환 모드와 시작 점검 검증 (2026-10-24)

`-Provider OpenRouter -OpenRouterCompat`은 `.env.openrouter`의 선택 모델을 모든 Claude 모델 역할에 사용하며 Plan 로그인·전환을 차단합니다. 기존 일반 실행과 Local 모드는 유지합니다. 대화형 시작 시 제공자별 최소 추론을 1회 수행하고, 점검 실패도 CLI 진입을 계속합니다. 일반 모드의 Plan fallback과 별도 모드의 Plan 차단 정책을 각각 유지합니다.

공개 Node 회귀 테스트 342개와 Python 테스트 64개, 실행기 자체 점검이 통과했습니다. 역할별 모델 매핑, 제공자 인증 분리, thinking·추론 강도·도구 참조·메타데이터 보존, 미지원 기능 거절, 인증·빈 응답·모델 불일치·타임아웃·cooldown 후 복구와 클라이언트 취소를 확인했습니다. OpenRouter 호환 모드의 모든 모의 upstream 호출은 OpenRouter 고정 주소만 사용했으며 Plan 호출은 없었습니다. 모든 대화형 모드에서 실패한 점검 뒤 프록시·CLI 시작 순서와 기존 Plan 허용 여부를 검사했습니다.

실제 Claude Code 2.1.304를 Windows ConPTY에서 실행하고, 제공자 응답만 합성 fixture로 대체했습니다. 개인 설정 대신 격리된 설정·플러그인·stdio MCP를 사용했습니다. 점검의 HTTP 503 실패 뒤에도 CLI가 시작돼 같은 세션에서 응답했으며, 별도 시작의 점검 성공도 확인했습니다. MCP 연결·ToolSearch의 지연 도구 검색·MCP 도구 호출·플러그인 이름공간 스킬 로드, SessionStart·PreToolUse·PostToolUse hook, 플러그인 하위 에이전트 시작·완료 알림을 관찰했습니다. 기본 권한 모드를 유지했으며 Plan 인증 조회는 테스트에서 금지했습니다. 초기 도구 호출 미확인은 합성 응답기가 ToolSearch를 호출하지 않은 테스트 결함으로, fixture를 보완한 후 MCP 호출을 확인했습니다.

프로세스 종료 회귀의 첫 실행은 새 시작 점검이 기존 stalled-upstream fixture에서도 대기해 준비 시간 초과가 발생했습니다. 종료 전용 테스트에서 시작 점검만 mock하고 실제 프록시·CLI·Bash 자식과 활성 연결의 정리 검증은 유지한 뒤 모두 통과했습니다. 시작 점검 자체는 별도 공개 테스트와 위 TTY 실행에서 확인했습니다.

이 환경에는 OpenRouter 실제 키 파일이 없어 **선택한 실제 OpenRouter 모델의 유료 추론과 기능 호환성은 미검증**입니다. 합성 API 성공을 실제 모델 지원으로 해석하지 않습니다. OpenRouter의 반복 자동 압축·장시간 실행·모든 플러그인 조합과 추론 강도의 실제 효과는 미검증이며 실제 서버 내부 연산 취소도 확인하지 않았습니다. 개인 주소·키·모델 설정과 원본 이력은 공개하지 않습니다.

## Local 호환 모드 검증 (2026-10-24)

`-Provider Local -LocalCompat`을 별도 선택 모드로 추가했습니다. 기존 일반 실행과 `-LocalMode`는 유지합니다. 현재 설정 서버·모델과 실제 Claude Code 2.1.304 TTY에서, 개인 플러그인·MCP 설정을 실행하는 대신 격리된 합성 플러그인과 stdio MCP를 사용했습니다.

| 항목 | 확인한 범위 |
| --- | --- |
| 플러그인·스킬 | 테스트 플러그인의 이름공간 명령으로 스킬 로드 및 MCP 도구 실행 |
| MCP | stdio 도구 검색·승인·호출·결과 왕복; ToolSearch의 정의된 도구 참조 이력 보존 |
| hooks | SessionStart·PreToolUse·PostToolUse 실행 표식 |
| 하위 에이전트 | 플러그인 에이전트 시작·백그라운드 실행·MCP 승인·완료 알림·주 대화 응답 |
| 압축 후 유지 | 같은 세션에서 `/compact` 완료 후 MCP·스킬·하위 에이전트 반복 성공; 각 도구 표식 총 2회 |
| 추론 설정 | `/effort low`·`/effort high`가 요청의 `output_config.effort`에 반영되고 응답 성공 |
| 인증·모델 | CLI에는 임시 프록시 인증만 전달; 모든 모델 역할은 설정한 같은 Local 모델로 매핑; Plan 라우팅 0회 |

호환 모드에서는 CLI의 알려진 beta, per-turn system 메시지와 출력 설정, `context_management`, thinking 표시 설정, custom 도구의 deferred/strict 설정을 검증한 뒤 보존해 전달합니다. 이전 Local 모드의 네이티브 제한을 완화하지 않습니다. 서명과 공급자 메타데이터는 타입을 확인하고 보존하며, 합성 회귀 테스트에서 thinking·도구 이력의 후속 요청 왕복을 확인했습니다. 토큰 계산 API는 명시적으로 거절하며, 실제 CLI는 해당 거절 이후에도 위 작업과 압축을 진행했습니다.

저장된 `settings.json.env`에 합성 주소·API 키·Bearer·사용자 정의 인증 헤더·잘못된 모델을 넣은 별도 TTY 실행에서도 최상위 실행 설정이 프록시 경로와 임시 인증을 유지했습니다. 실제 Local MCP 호출과 응답에 성공했고 기본 승인 프롬프트도 유지됐습니다. 서버 키를 CLI에 넘겨 해결하지 않았습니다.

ToolSearch 참조 보존까지 적용한 마지막 실행은 Local 라우팅 4회, Plan 라우팅·네이티브 거절·외부 시도 실패 0회였습니다. CLI 종료 코드 0과 CLI·프록시 종료를 확인했고, 생성한 임시 CLI 설정과 대화 이력은 삭제했습니다.

현재 서버의 JSON 응답은 설정 모델과 일치했으나 직접 SSE 추론 응답의 `message_start.model`은 일치하지 않았습니다. 이를 우회해 허용하지 않고, JSON 응답 전체를 검증한 뒤 CLI용 SSE로 변환합니다. 실시간 토큰 전달은 제공하지 않습니다. 120초 전체 요청 제한·외부 시도 1회·30초 cooldown과 Plan fallback 차단을 유지합니다.

추론 강도 값 수용과 실제 모델 내부 추론량의 변화는 구분합니다. 직접 추론 점검에서는 low/high·adaptive/enabled 설정이 수용됐지만 별도 서명된 thinking 블록은 확인하지 못했습니다. HTTP/SSE 방식의 원격 MCP, 임의의 개인 플러그인 조합, 모든 hooks 이벤트, IDE·Chrome, 서버 고유 기능, 이 호환 모드의 시간 단위 연속 실행·반복 자동 압축은 이번 검증 범위에 포함하지 않았습니다. 실제 LLM 서버 내부 연산 취소도 계속 미검증입니다.

공개 회귀 테스트는 Node 286개, Python Local 설정·수명주기 47개가 통과했고 실행기 자체 점검과 diff 공백 검사도 통과했습니다. 서버 주소·키·실제 모델 이름·세션 식별자·원본 요청/응답은 공개 파일에 포함하지 않았습니다.

## 외부 호출 없는 점검

```powershell
node --test tests/*.test.mjs
python -m unittest discover -s tests -p 'test_*.py' -v
python openrouterAdvisor.py --self-test
```

1. 정상 JSON/SSE 응답과 도구 호출·결과 왕복이 보존되는지 확인합니다.
2. 빈 응답, 잘린 스트림, 연결 거부, 타임아웃을 모의 주입합니다.
3. 최초 요청과 재시도 3회 실패 후 Plan fallback, cooldown 후 외부 경로 복구를 확인합니다.
4. 취소된 요청은 재실행하지 않고, 이미 전달한 스트림 뒤에 다른 제공자의 응답을 붙이지 않는지 확인합니다.
5. OAuth는 구독 경로에만, 외부 제공자 키는 선택한 외부 경로에만 전달되는지 합성 인증값으로 확인합니다.
6. 알 수 없는 기능·서명된 이력은 삭제하지 않고 구독 경로로 보존하는지 확인합니다.

## 별도로 필요한 실환경 점검

실제 호출은 데이터 전송·과금 범위를 사전에 정하고 합성 입력으로 최소화하세요. 키와 원문 로그를 출력하거나 커밋하지 마세요. HUD·이력·MCP는 설정 로드와 실제 기능 동작을 구분해 점검하세요. HTTP 429는 계정 상태와 응답을 확인해야 하며, 모의 검사로 구독 경로 성공을 주장해서는 안 됩니다.

Local 모델 목록 조회 성공은 추론·스트리밍·도구 지원의 증거가 아닙니다. 실제 Local 서비스와 모든 네이티브 기능의 동등성은 별도 검증 대상입니다.

## Local 모드의 긴 대화·압축 점검

사용자 대화와 분리한 임시 설정 디렉터리와 새 세션을 사용합니다. 합성 식별자, 선택 값, 남은 작업을 기억시킨 뒤 무관한 합성 기록으로 대화를 늘립니다. 실제 키·내부 주소·대화 원문은 결과에 남기지 않습니다.

1. `-Provider Local -LocalMode` 세션에서 `/compact`를 실행하고, 다음 요청에서 원래 정보를 다시 제시하지 않은 채 회상하는지 확인합니다.
2. 지원하는 CLI에서는 이번 실행에만 `--autocompact 100k`를 지정합니다. 실제 입력 토큰이 임계값을 넘은 뒤 다음 요청까지 진행합니다. CLI의 자동 압축 창은 최소 100k이며, 서버도 해당 입력 길이를 지원해야 합니다. 설정 저장을 피하려면 `/autocompact` 대신 실행 옵션을 사용합니다. [공식 자동 압축 안내](https://code.claude.com/docs/en/model-config#adjust-the-auto-compaction-window)
3. 임시 세션 이력의 `compact_boundary`에서 수동·자동 트리거와 압축 전후 토큰 수를 확인합니다. 옵션 활성화나 긴 입력 성공만으로 자동 압축 성공을 판단하지 않습니다.
4. 압축 뒤 핵심 정보 회상과 새 응답이 성공하는지 확인합니다. `route_selected`는 `provider: local`이어야 하며, Plan 요청이 없어야 합니다.
5. 출력 예산 회귀 검사는 임시 부모 환경·사용자 설정·프로젝트 설정에 2,048을 지정하고 반복합니다. Local 실행 설정이 8,192를 적용하는지 실제 전송 예산으로 확인한 뒤, 큰 이력의 자동 압축을 두 번 수행하고 매번 도구 실행·핵심 정보 회상을 검증합니다. 더 높은 부모 예산은 유지하고, 일반 실행과 진단의 예산은 바뀌지 않아야 합니다. CLI가 컨텍스트 여유 때문에 예산을 낮춘 요청은 프록시가 다시 올리지 않아야 합니다.

Local 모드는 요청당 120초를 허용합니다. 시간 초과 시 한 번 실패하고 Plan으로 전환하지 않습니다. CLI 자체의 재시도는 추가될 수 있습니다. 수동·100k 자동 압축 통과가 전체 컨텍스트 한도, 반복 압축, 장시간 도구 작업을 보장하지는 않습니다.

## 한 시간 연속 실행 결과

코드 `5401a96`, Claude Code 2.1.304에서 같은 CLI 프로세스와 Local 전용 프록시를 3,621.83초 유지했습니다. `stream-json` 입력을 열린 상태로 두고 순서대로 요청했습니다. 자동 압축 창은 `100k`, 출력 예산은 8,192였으며, 시각적 대화형 터미널은 점검 범위에 포함하지 않았습니다.

처음에만 제시한 합성 정보를 반복 압축 뒤 회상하도록 했습니다. 도구 작업은 임시 파일에서 매번 새 값을 Read로 읽고, Edit로 다른 파일을 수정하고, Bash로 정해진 합성 문자열을 출력하도록 구성했습니다. 원래 정보는 후속 입력이나 파일로 다시 제공하지 않았습니다.

|---|---|
| Local 서버 요청 | 157회 |
| 자동 압축 경계 | 22회, 이 중 토큰 수가 50,000보다 많이 줄어든 압축 11회 |
| Read·Edit·Bash 작업 묶음 | 40회 성공 |

실패 없이 끝난 실행은 아닙니다. 약 807초에 서버가 HTTP 200과 빈 내용을 반환해 요청 1회가 실패했습니다. 35초 대기 후 같은 CLI·프록시에서 짧은 요청으로 복구했고, 이후 압축·도구 작업을 계속했습니다. 이는 120초 시간 초과와 다른 실패입니다. 한 시간 실행에서는 시간 초과 이후의 복구를 시험하지 않았으며, 아래 별도 시험에서 지연 주입으로 확인했습니다.

한 시간 측정에 앞선 별도 준비 실행에서 회상 판정 실패가 1회 있었으며, 정확한 원인은 확인하지 못했습니다. 이 준비 실행은 위 집계에서 제외했습니다. 한 시간 결과는 합성 입력과 해당 버전·설정에 한정되며, 더 긴 실행이나 모든 서버 응답의 안정성을 보장하지 않습니다. 원문 로그와 개인 설정은 공개하지 않습니다.

## 120초 시간 초과 이후 같은 Local 세션의 복구
