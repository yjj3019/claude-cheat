# 보안 모델과 잔여 위험

이 문서는 `claude-cheat`의 실행기·프록시·대시보드가 **무엇을 신뢰하고 무엇을 방어하는지** 정리합니다. 코드가 바뀌면 이 문서도 함께 갱신하세요.

## 1. 신뢰 경계

| 구성 요소 | 위치 | 신뢰 |
| --- | --- | --- |
| 라우팅 프록시 | `127.0.0.1:<임시 포트>` | 로컬 사용자만 접근. `X-Local-Route-Token`(세션마다 생성) 없으면 403 |
| 대시보드 | `127.0.0.1:8787` (고정) | 로컬 사용자만 접근. 읽기는 공개, 쓰기는 시작 시 `write_url`로 전달되는 쓰기 토큰 필요 |
| 설정 파일 | 실행기 폴더의 `openclaude.config.yaml` 한 파일(예전 `.env.openrouter` / `.env.local-llm`은 읽기 전용 폴백, 폐기 예정) | 사용자 소유 파일. Git 제외(`openclaude.config.yaml*`, `.env.*`). 같은 폴더의 `.bak`·임시 파일도 제외 |
| 로그·메트릭 | `.route.log`, `.proxy-metrics.json` | 진단용. 키·프롬프트·본문은 기록하지 않음. 턴별 `traceId`로 상관, sink에서 자격증명 패턴 세척 |

프록시와 대시보드는 **모두 루프백에만 바인딩**합니다. 외부 인터페이스로 열리는 경로는 없습니다.

## 2. 인증·인가

| 대상 | 통제 |
| --- | --- |
| 프록시 `/v1/messages` | `X-Local-Route-Token`(32바이트 랜덤, 상수시간 비교) + OAuth Bearer(`sk-ant-oat…`) 필요. Plan 경로는 추가로 first-party 로그인 확인 |
| 프록시 `/api/metrics` | 같은 세션 토큰 필요 |
| 프록시 `POST /api/handover` | 같은 세션 토큰 필요. 새 요청에는 503(+`Retry-After`)을 주고 진행 중인 턴만 마친 뒤 종료합니다(기본 상한 120초). 상한을 넘기면 **종료 대신 서비스로 되돌리고 409**(`reverted: true`)로 알립니다. 동시 요청은 하나의 드레인으로 합쳐집니다 |
| 대시보드 종료(`--stop`·시작 시 이전 인스턴스) | `.dashboard.pid`의 **pid + 프로세스 생성시각**이 모두 일치할 때만 SIGTERM. 불일치·자기/상위 pid·신원 없는 구버전 기록은 거부하고 한 줄로 보고(pid 재사용으로 무관한 프로세스를 죽이는 사고 방지) |
| 대시보드 쓰기(`POST /api/config`, `/api/test`) | **쓰기 토큰**(시작 시 출력되는 `write_url`의 `#token=…` 프래그먼트로만 전달, 페이지 HTML에는 없음. 브라우저는 그 탭의 `sessionStorage`에 보관해 화면 이동·새로고침을 견디고 탭 종료 시 삭제. 대시보드는 토큰을 `.dashboard.token`(같은 사용자 파일)에 보관해 재시작해도 유지) **+ 동일 출처(Origin)** 검사 + **분당 30회 제한**(초과 시 429). `/api/test`는 동시에 1개만 실행되고 초과분은 `test_busy` |
| 대시보드 설정 조회(`GET /api/config`) | **쓰기 토큰** 필요. 값은 마스킹되어 내려가며, 토큰이 없거나 ASCII가 아닌 토큰은 403 JSON |
| 대시보드 읽기(`/`, `/api/status`, `/api/snapshot`) | 인증 없음. 루프백 한정 + **Host 허용목록**. 세션 토큰은 포함하지 않으며, 상태 응답에는 설정 여부·현재 세션 provider·시작 시각·모델명·로그 파일 경로와 프록시 **프로세스 상태(pid·RSS·힙·이벤트 루프 지연)** 가 포함됩니다(비밀값 아님). 같은 PC의 다른 사용자는 프로세스 목록을 이미 볼 수 있어 pid는 추가 노출이 아닙니다 |
| 연결 테스트 입력 | 저장하지 않은 폼 값 중 반영되는 것은 **모델 ID·타임아웃**뿐입니다. 서버 주소·API 키·CLI 실행 파일은 항상 저장된 값만 사용하므로, 작성 중인 주소로 저장된 키를 보내거나 게시한 경로의 실행 파일을 구동할 수 없습니다 |
| 비밀값 | 응답에 절대 포함하지 않음(`sk-or-…ccd0` 마스킹). 저장 시 빈 값이면 기존 키 유지 |
| 서버 주소 | Messages·HTTP 예외·모델 목록 주소도 응답에 원문을 담지 않고 호스트 앞뒤 2자만 보이게 마스킹(`user:pass@`·쿼리·프래그먼트는 제거, 표준 경로가 아닌 사용자 지정 path는 `/•••`). 연결 테스트·모델 목록 응답에도 주소를 싣지 않음. 선택 주소는 `clear` 목록으로만 삭제 |
| 설정 파일 쓰기 | 제한된 YAML 부분집합만 허용하고, 읽을 수 없거나(인코딩·문법 오류) 형식이 틀린 파일은 **덮어쓰지 않음**. 제어문자·U+2028/2029/0085가 든 값은 거부. 저장은 스레드 락 + **프로세스 간 잠금 파일**(`.openclaude.config.yaml.lock`) 안에서 다시 읽고 → 고유 임시 파일 → 원자적 교체(Windows 점유 시 재시도)이며 실패하면 원본 유지. 백업은 **이전 파일의 바이트 그대로**이고(POSIX에서는 0600), CRLF·BOM·관리 키의 inline 주석은 보존. 섹션이 아직 없는 서비스를 저장할 때는 예전 `.env` 값을 함께 옮겨 자격증명이 가려지지 않게 함. 오류에는 코드와 줄 번호만 포함하고 값은 싣지 않음 |
| CLI 진단 실행 | 설정 화면의 연결 테스트가 설치된 CLI(Codex·Grok·Claude Code)를 **셸 없이** 직접 실행합니다. 허용 목록 환경만 전달(`ANTHROPIC_BASE_URL`·키·대시보드 토큰 제외, `claude -p`의 자기 호출 재귀 방지), 빈 임시 폴더, 프롬프트는 고정 문자열을 파일/표준 입력으로 전달, 출력은 파이프가 아닌 파일로 받아 크기 상한과 시간 제한을 두고 초과·시간 초과 시 프로세스 트리를 종료, 동시 1개. 실행 파일은 절대 경로·이름 일치·존재를 확인하고 **UNC 경로와 심볼릭 링크는 거부**하며(하드 링크는 여전히 구분 불가), npm `.cmd` 래퍼는 해석해서 `cmd.exe`를 거치지 않음. Windows에서는 자식 프로세스를 **kill-on-close Job Object**에 넣어 루트가 먼저 끝나도 남은 손자 프로세스를 실행 종료 시 정리함(할당 실패 시 기존 taskkill 폴백). 결과에는 분류·종료 코드·소요 시간만 담고 CLI 출력·오류 원문은 표시·기록하지 않음. **CLI는 에이전트이므로 도구 차단 플래그의 효과는 검증되지 않았음**(신뢰할 수 없는 입력 전송 금지). `GET /api/cli`는 세션 토큰 필요 |
| 요청 구성 계측 | 프록시가 요청마다 내용 없는 `request_shape` 이벤트(모델 계열·도구 유무 등 불리언/열거값)만 경로 로그에 기록. 모델 ID·프롬프트·도구 이름·식별자는 기록하지 않음 |
| 듀얼 프로바이더(옵트인) | `routing: dual_provider: true`이고 두 서비스가 모두 설정된 **일반 세션**에서만 다른 provider가 `/model` 항목 하나로 노출됩니다. 다른 provider의 자격증명은 프록시 프로세스에만 전달되고 CLI 환경변수(인증 점검 자식 포함)에는 절대 들어가지 않으며, 별칭 모델 id는 특수 모드(local-only·호환)에서 인식되지 않아 그 모드의 보장을 우회할 수 없습니다. 서킷 브레이커는 provider별로 분리됩니다. 인수인계는 기록된 별칭 토폴로지(provider·별칭·모델 id)를 검증해 드레인 전에 거절할 수 있고(자격증명은 없고 세션 nonce만 포함, §7.9), 자격증명은 항상 현재 설정에서 재구성합니다 |

### CSRF를 별도 토큰 없이 막는 이유

- 세션 쿠키를 **쓰지 않습니다**. 인증은 `write_url` 프래그먼트로 받아 그 탭의 `sessionStorage`에만 두는 값 + 커스텀 헤더(`x-dashboard-token`)입니다. `sessionStorage`는 출처·탭 범위라 다른 탭·다른 프로세스가 읽을 수 없고 탭을 닫으면 사라집니다.
- 커스텀 헤더가 필요한 요청은 브라우저가 **프리플라이트**를 보내므로, 다른 출처에서는 헤더를 붙일 수 없습니다.
- 추가로 `Origin`이 있으면 `127.0.0.1`/`localhost`/`[::1]` 중 하나일 때만 쓰기를 허용합니다. Origin이 없는 요청(스크립트·curl)은 토큰과 Host 검사만 통과하면 허용됩니다.
- 따라서 별도 CSRF 토큰은 중복 방어이며, 추가하지 않았습니다.

### DNS 리바인딩

- 브라우저가 `evil.example`을 127.0.0.1로 해석해도, 요청의 `Host`가 `127.0.0.1`/`localhost`/`[::1]`이 아니면 **403 `host_rejected`**.
- 읽기 응답에는 CORS 헤더를 보내지 않으므로 다른 출처의 JS가 본문을 읽을 수 없습니다.

## 3. 헤더·전송

- 대시보드의 모든 응답과 프록시의 거부·진단 응답: `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`.
- TLS는 사용하지 않습니다(루프백 전용). 외부 구간(OpenRouter/Anthropic)은 프록시가 HTTPS로 통신합니다.
- 인증서·프록시 설정을 신뢰하지 않기 위해 `ProxyHandler({})`로 시스템 프록시를 우회합니다.
- 대시보드의 모델 목록·연결 점검은 HTTP 리다이렉트를 따르지 않습니다. 검증된 최초 주소 외의 목적지로 제공자 인증을 전달하지 않으며 3xx는 정제된 HTTP 오류로 보고합니다.
- 대시보드 HTTP 핸들러는 소켓 타임아웃(15초)을 두어 헤더를 천천히 보내는 연결이 스레드를 오래 점유하지 못하게 하고, **동시 연결 64개**(`DashboardServer.max_connections`)를 넘는 소켓은 새 스레드를 만들지 않고 즉시 닫습니다. 리스너 대기 큐도 64입니다.

## 4. 입력 검증

| 입력 | 검증 |
| --- | --- |
| 모델 ID | `[A-Za-z0-9~@][A-Za-z0-9._:/@+~-]{0,255}` |
| OpenRouter 키 | `sk-or-[A-Za-z0-9_-]+` |
| Local URL | `http(s)`, `/v1/messages` 경로, 루프백(또는 명시 허용한 HTTPS/사내 HTTP 예외) |
| 모델 목록 URL | 같은 출처 또는 명시 설정, `http(s)` |
| 요청 본문 | `Content-Length` 0~64KB, 음수 거부, JSON 객체만 |
| 프록시 본문 | 최대 32MiB(토큰 계산은 4MiB), 엄격한 필드 화이트리스트(알 수 없는 필드는 Plan 우회). 동시 처리 32개·진행 중 본문 합계 64MiB로 상한을 두고, 초과 시 429/503(+`Retry-After`) |
| 요청 유휴·총 시간 | 본문·헤더가 30초(기본, `ROUTE_REQUEST_IDLE_TIMEOUT_MS`) 동안 진행하지 않으면 연결을 끊고 점유 턴을 반납. 추가로 본문 업로드 전체에 60초 절대 기한(`ROUTE_REQUEST_TOTAL_TIMEOUT_MS`)을 두어 1바이트씩 트리클링하는 업로드가 드레인을 막지 못하게 함 |

`LOCAL_LLM_*` URL은 사용자가 직접 설정하는 값이며, 형식 검증만 수행합니다. **신뢰할 수 없는 출처의 URL을 넣지 마세요**(SSRF 표면).

## 5. 비밀값 취급

- 키는 `openclaude.config.yaml`(Git 제외, 예전 `.env.*` 포함)에만 존재하고, 자식 프로세스 env로 전달된 뒤 **프록시 시작 시 env에서 삭제**됩니다.
- 로그에는 키·프롬프트·요청 본문을 남기지 않습니다(`route_selected`, 실패 코드, traceId, 바이트 수만). 모든 진단 출력은 **단일 sink**를 지나며, 설정된 키·`Bearer …`·`sk-*`·`x-api-key` 값을 `[redacted:provider-key|bearer-token|api-key]` 태그로 바꿉니다(모델명·상태코드·traceId는 유지). 같은 세척을 프록시가 만드는 오류 응답과 전달하는 Plan 오류 본문에도 적용하며, `.route.log` 미러에도 같은 세척을 거친 문자열만 기록합니다.
- 제공자 오류 본문은 **최대 64KiB**까지만 읽어 세척 후 전달하고 나머지는 취소합니다. Plan 오류 읽기도 취소·본문 유휴 제한을 적용하며, 잘린 경우 `upstream_error_truncated` 이벤트를 남깁니다. 로그에는 원문 발췌(excerpt)를 남기지 않고 길이·바이트 수만 기록합니다.
- 일반 모드의 SSE thinking 블록·델타는 전달 전에 거부합니다(명시적인 호환 모드의 reasoning 허용은 유지). `message_start`의 content는 생략 또는 빈 배열만 허용해 블록 검증 우회를 막습니다. passthrough에서 이미 전송한 정상 텍스트는 이후 오류가 나도 회수할 수 없으며 fallback하지 않습니다.
- 메트릭의 `last.status`는 HTTP 상태이고 `last.outcome`은 완료 결과(`ok`·`failed`·`aborted`)입니다. HTTP 200 이후 스트림 오류도 실패로 집계합니다. 대시보드의 현재 경로는 마지막 프록시 시작 이후 결정만 사용하며, 시간창 누계는 이전 세션 이력을 포함할 수 있습니다. 경로 선택 로그는 추론 완료나 프로세스 생존의 증명이 아닙니다.
- 세척은 패턴 기반이므로 **난독화·분할된 자격증명**은 탐지하지 못할 수 있습니다. 근본 통제는 키를 로그·본문에 넣지 않는 것입니다.
- 설정 저장은 **원자적 교체**(임시 파일 → rename) + 이전 내용 `.bak`. 읽기 실패 시 파일을 건드리지 않습니다. 대시보드는 잠금 안에서 최신 값과 합친 실제 저장 후보를 다시 검증하며, 검증 실패 시 원본과 백업 모두 변경하지 않습니다. 잠금 파일을 열 수 없거나 잠금을 얻지 못하면 **저장하지 않고 `config_busy`로 실패**합니다(잠금 없이 진행하지 않음).
- `installLauncher.ps1`의 포워더는 체크아웃 경로만 담고, 자기 자신을 덮어쓰거나 지우지 않습니다(마커 검사).

## 6. 하지 않은 것과 그 이유

| 항목 | 결정 |
| --- | --- |
| 요청 속도 제한(읽기) | 상태·스냅샷 같은 주기 갱신 읽기는 제한하지 않습니다. 다만 `GET /api/models?refresh=1`은 업스트림을 다시 호출하므로 분당 6회로, `/api/test`는 동시 1개로 제한하고, 쓰기 API는 분당 30회로 제한합니다 |
| 별도 CSRF 토큰 | 2절의 이유로 불필요 |
| TLS(로컬) | 루프백 전용. 인증서 관리 비용 대비 이득 없음 |
| 의존성 취약점 스캔 | 런타임 의존성 **0개**(Node 표준 라이브러리, Python 표준 라이브러리) |
| 명령 실행 샌드박스 | 이 도구는 라우팅만 담당하며, 도구 실행 권한은 Claude Code 세션 설정을 따릅니다 |

## 7. 잔여 위험

1. **로컬 사용자 신뢰**: 같은 PC의 다른 사용자·프로세스는 루프백 포트에 접근할 수 있습니다. 읽기(대시보드)는 여전히 공개이므로 공용 PC에서는 대시보드를 띄우지 마세요. 쓰기 토큰은 페이지가 아니라 시작 시 출력되는 `write_url`로만 전달되지만, 그 URL을 붙여넣거나 화면 공유하면 노출됩니다.
2. **쓰기 토큰 노출 경로**: 토큰은 페이지 HTML·응답 본문에 없고 그 탭의 `sessionStorage`에만 있지만, 브라우저 확장·DevTools·화면 공유·콘솔 기록으로 노출될 수 있습니다. 또한 시작 시 콘솔에 출력되는 `write_url`과 `--open`으로 브라우저를 띄울 때의 브라우저 프로세스 인자에는 토큰이 포함될 수 있으므로, 같은 사용자 권한의 프로세스는 이 경로로 읽을 수 있습니다(이미 같은 OS 사용자 신뢰 경계 안). 토큰은 재시작 후에도 유지되도록 `.dashboard.token`에 저장되므로 같은 사용자 프로세스·백업·동기화 도구가 이 파일을 볼 수 있습니다. 노출되면 그 토큰을 아는 동안 설정 저장과 CLI 진단 실행이 가능합니다. **토큰을 교체하려면 `.dashboard.token`을 삭제**하거나 `DASHBOARD_TOKEN` 환경 변수로 지정한 뒤 대시보드를 다시 시작하세요.
3. **SSRF**: `LOCAL_LLM_*` URL은 사용자가 저장한 값입니다. 신뢰할 수 없는 값을 저장하지 마세요(연결 테스트는 저장된 주소만 사용합니다).
4. **자격증명 세척의 한계**: 로그·오류 본문 세척은 패턴 기반입니다. Base64·분할·변형된 키는 통과할 수 있고, 64KiB를 넘는 오류 본문은 잘립니다.
5. **프로세스 신원 검증의 한계**: 대시보드 종료는 pid+생성시각이 일치할 때만 수행하며, 검증과 신호 사이의 아주 짧은 TOCTOU 창은 남습니다(pid+생성시각 충돌은 사실상 불가능). 비Windows에는 생성시각 조회 수단이 없어 종료를 거부합니다. 업그레이드 직후 구버전 대시보드는 한 번 직접 종료해야 합니다.
6. **CLI 진단 실행 파일**: 고정(pinned) 실행 파일은 절대 경로·이름 일치·존재를 확인하고 UNC 경로/심볼릭 링크를 거부하지만, **하드 링크**는 같은 파일의 다른 이름이라 구분하지 못합니다. 설정 파일을 쓸 수 있는 사람은 어차피 그 경로를 실행시킬 수 있으므로 설정 파일 접근을 신뢰 경계로 보세요(경로는 대시보드 응답에도 일부 노출).
7. **CLI 진단 프로세스 정리**: Windows에서는 kill-on-close Job Object로 손자 프로세스를 정리하지만, 프로세스를 Job에 넣기 **전**(spawn 직후 아주 짧은 창)에 자식이 손자를 만들면 누락될 수 있고, Job 할당이 실패하면 기존 taskkill 폴백으로 돌아갑니다. 라우팅 세션의 Local 모드는 별도 Job/guardian으로 보호됩니다.
8. **감사 범위**: 정적 검토 + 회귀 테스트이며, 침투 테스트는 수행하지 않았습니다(퍼징은 별도 스위트).
9. **세션 핸드오프 파일**: `.session-handoff.json`에는 프록시 포트·pid와 함께 세션 nonce가 들어 있습니다. 파일 접근 권한이 경계이며, 같은 사용자 권한의 프로세스는 이 값을 읽어 프록시에 요청할 수 있습니다(로컬 신뢰 경계와 동일). 파일은 Git 제외 대상이고 원자적으로 쓰입니다.
10. **CLI 진단 자식 프로세스 인자**: 격리 세션에서 CLI에 넘기는 `--settings` JSON에는 라우팅 nonce가 포함됩니다. 같은 사용자 권한의 프로세스가 프로세스 목록을 읽을 수 있는 환경에서는 짧게 노출될 수 있습니다.
11. **블랙박스 기록 동의**: 블랙박스는 기본 꺼짐이고 상세 기록은 사용자가 명시적으로 선택해야 시작됩니다. 상세 기록은 `.blackbox/recording.json`(최대 2MiB·256이벤트)에 경로 로그 이력을 마스킹해 보관하지만, 패턴 기반 마스킹은 모든 비밀·민감정보를 제거한다고 보장하지 않으므로 기록 파일은 비밀값과 동급으로 다루고 공유하지 마세요.
12. **로그 한 줄 보장**: `.route.log` 미러는 삽입된 개행을 공백으로 바꿔 한 이벤트가 여러 줄을 위조하지 못하게 하지만, JSON 구조 로그 자체는 값 안의 개행을 이스케이프할 뿐 내용 검증은 하지 않습니다.
13. **`--print` 프롬프트**: 실행기는 프롬프트를 argv가 아니라 **표준 입력**으로 넘겨 프로세스 목록에 남지 않게 합니다. 다만 Claude Code가 stdin을 읽는 방식(기본 `--input-format text`)에 의존하므로, 아주 오래된 CLI나 비표준 래퍼에서는 동작이 다를 수 있습니다.
14. **대시보드 포트 스쿼트**: 같은 사용자가 8787을 먼저 점유하면 대시보드는 시작을 거부합니다(자동 대체 포트는 `--allow-port-fallback`을 명시할 때만, 그때도 출력된 URL의 Host를 확인). 점유 자체를 막을 수는 없으므로 시작 실패를 무시하고 다른 프로세스에 토큰을 보내지 마세요.
15. **CLI 해석 불일치**: 실행기는 `shutil.which` 결과를, 프록시 CLI 백엔드는 자체 탐지 결과를 씁니다. 둘 다 절대 경로·이름 검사를 하지만 서로 다른 바이너리를 가리킬 수 있습니다(예: PATH 변경 시). 같은 세션에서 버전이 다르면 진단 출력의 경로를 확인하세요.
16. **`.cmd` shim 폴백 (2026-11-07)**: 실행기는 npm `.cmd` shim을 `[node, script]`로 풀어 cmd.exe 재해석을 피하지만, shim을 파싱하지 못하면 원래 경로로 실행하는 폴백이 남습니다(격리 모드는 메타문자 경로를 이미 거부). 파싱 불가 shim을 발견하면 경고의 안내대로 네이티브 `claude.exe`를 쓰는 것이 좋습니다.
17. **takeover 소유 확인의 한계 (2026-11-07)**: 런처는 CLI를 시작하기 전에 포트가 자기 프록시인지 nonce로 확인하지만, 확인 이후의 짧은 창까지 막지는 못합니다. 같은 사용자 권한의 프로세스가 그 창에 끼어드는 것은 로컬 신뢰 경계의 잔여 위험입니다.

## 8. 확인 방법

```powershell
# 외부 Host 거부
Invoke-WebRequest -Uri 'http://127.0.0.1:8787/api/status' -Headers @{ Host = 'evil.example' }

# 토큰 없는 쓰기 거부
Invoke-WebRequest -Uri 'http://127.0.0.1:8787/api/config' -Method Post -Body '{}' -ContentType 'application/json'

# 프록시 토큰 없는 접근 거부
Invoke-WebRequest -Uri 'http://127.0.0.1:8787/api/models?provider=openrouter'

# 시작 로그의 write_url로만 쓰기 토큰을 얻습니다.
python routeDashboard.py --port 8787
# → {"dashboard":"http://127.0.0.1:8787/","write_url":"http://127.0.0.1:8787/#token=…",…}
```
